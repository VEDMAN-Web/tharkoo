# H5.9: No em dash or en dash on the site (relay #42)

## Done
- Code defaults: home SEO title "Tharkoo | Free classifieds in India"; ad title template "{title}, {city} {category} | {site}" (also in src/lib/seo.ts); admin copy, trust placeholder, support hours and the SEO check output use commas, colons, full stops or hyphens.
- Stored data: `repairDashes` (src/server/content/dash-repair.ts) walks Site, SiteSettings, SeoTemplate, Category, Location, UrlOverride, PageLayout(+Revision), UiText, ContentPage and Page. Title-like keys get " | ", other text gets ", ". Idempotent. Runs from the seed and from a superadmin route: POST /api/admin/repair/dashes.
- Prevention: forbidden-terms rule for both dashes (.github/forbidden-terms.txt); SEO template save and URL override save refuse dashes with "Use a comma, a colon or a full stop instead of a dash"; the generic admin save for SeoTemplate, UrlOverride, Category, Location and Site refuses them too (400).
- Dash characters are built from character codes in the source, so the source has none.

## Not done
- Vedant or Opus runs POST /api/admin/repair/dashes as superadmin on staging and production after the deploy (no admin button added yet).

## Verification
- tests/server/content/dashes.test.ts: detection, refusal, repair, second run changes nothing.
