# H18.3 — Delete a category or sub-category even when it has ads

Done by Opus directly (Vedant, 21 Nov 2026: "when the admin wants to delete the entire category, it must be deleted despite having ads in it. Strict orders").

- `deleteCategory` / `deleteSubcategory` no longer refuse when ads exist. All ads in the category (or sub-category), real and sample, any status except removed/deleted, are set to `status: "removed"` in one `updateMany`, then sub-categories and the category are deleted. The audit entry now carries `adsRemoved`.
- Admin confirm dialogs (type the slug, unchanged) now say the ads are removed too.
- Tests: subcategories.test.ts and h8-51-screen.test.ts updated to the new rule (3 ads removed, other sub-category untouched, non-admin refused). The e2e "a category with ads cannot be removed" is skipped with a reason: the behaviour it asserted was removed on purpose; the server tests cover the new rule.
- Not done: no new undo for category deletion (none existed). Places/areas keep their "Hide it instead" rule (not in scope).
