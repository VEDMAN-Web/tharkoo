# H18.1 — PassimPay crypto checkout for credit packs

Done by Opus directly (Vedant, 21 Nov 2026).

- PAYMENT_PROVIDER=passimpay + ALLOW_LIVE_PAYMENTS=true + PASSIMPAY_PLATFORM_ID / PASSIMPAY_API_KEY (env names only) turn it on. Otherwise the mock/test flow is unchanged.
- Recharge: the Payment is created as today (provider "passimpay", providerRef = payment id), then a PassimPay invoice (INR amount, crypto only) is made and the buyer is sent to its page. The invoice URL is kept on the payment so a repeat reuses it.
- Credits: only when PassimPay's orderstatus says "paid" (and, for a rupee invoice, amountPaid >= price), through the existing applyWebhook path (idempotent). Triggered by the PassimPay notice (POST /api/payments/passimpay/webhook/, x-signature checked over the raw and re-serialised body; a valid notice only triggers the status check), and also when the buyer opens their payment or history (a lost notice still credits).
- Tests: tests/server/billing/h18-1-passimpay.test.ts (signature, request shape, wait/paid/once, underpaid, lost notice via history, webhook 400/200, live guard). Billing suite 12 files / 115 tests pass.
