# T3.1 Listings service and routes

## Routes
| Method | Path | Notes |
|---|---|---|
| GET | `/api/listings` | Session. Own rows. `listingQuerySchema`. |
| POST | `/api/listings` | Session. Creates a draft. `listingCreateBodySchema`. |
| GET | `/api/listings/by-id/{id}` | Owner or staff. Includes contact. |
| GET | `/api/listings/{slug}` | Public. Slug or 24-hex id. No phone, WhatsApp, or Telegram. Removed or deleted is 410. Draft, pending, rejected, paused, expired, and archived are 404 except to the owner, who still gets the public projection. |
| PATCH | `/api/listings/{id}` | Owner. Stages `basics`, `details`, `photos`. |
| DELETE | `/api/listings/{id}` | Owner. Soft status `removed`. Body `{ status: "removed" }`. |
| POST | `/api/listings/{id}/submit` | Owner. Draft or rejected to `pending`. `listingSubmitBodySchema`. |
| POST | `/api/listings/{id}/renew` | Owner. Active, paused, or expired. Adds 30 days. Expired returns to active. |
| POST | `/api/listings/{id}/pause` | Owner. Active to paused. |
| POST | `/api/listings/{id}/resume` | Owner. Paused to active. Past `expiresAt` is 409. |
| POST | `/api/listings/{id}/duplicate` | Owner. New draft. |
| GET | `/api/listings/{id}/versions` | Owner or staff. |
| POST | `/api/listings/{id}/contact` | Alias of contact reveal. |
| POST | `/api/listings/{id}/contact-reveal` | Active listings only. `contactRevealBodySchema`. |
| POST | `/api/cron/expire` | Header `x-cron-secret` must equal `CRON_SECRET`. Body `cronBodySchema`. |

Mutations call `assertOrigin`. Contact reveal sends `Cache-Control: no-store`. Each reveal writes `listing.contact_reveal` without the contact value. Other mutations write a listing audit row.

## Behaviour
- Publish calls `assertVerified`, then `evaluatePublishGate`. Uncleared media is `POLICY_VIOLATION` / `MEDIA_NOT_CLEARED`. An unapproved account is `VERIFICATION_REQUIRED`.
- Photos must belong to the caller and be `cleared`. The cap is `photoLimit` from T2.2 (`LISTING_PHOTO_LIMIT_FREE` default 1, `LISTING_PHOTO_LIMIT_PROMOTED` default 10).
- Banned text uses `textDenied` plus every `BannedWord.text`. A hit is `POLICY_VIOLATION` and does not save.
- `FREE_ADS_PER_WEEK` defaults to 3. The count is other listings this ISO week (Monday 00:00 UTC) with `attestations.submittedAt` set and a non-draft status. Over the limit is HTTP 429, `error.code` `FREE_LIMIT`, and `Retry-After`.
- A sensitive edit (title, description, category, contact, or photos) of an active listing sets `pending`, `seoNoindex`, and appends a `ListingVersion`.
- Submit also appends a version and sets `expiresAt` 30 days out. Status becomes `pending`, not `active`. Active is an admin transition and is not a route here.
- Cron sets `active` rows with `expiresAt` in the past to `expired`. A second call changes nothing.

## Model gaps (no schema edits)
- No contact encryption helper. `src/server/shared/crypto.ts` has hashes only. Phone, WhatsApp, and Telegram are stored plaintext on the existing `select: false` contact subdocument.
- No `submittedAt` field. The weekly counter uses `attestations.submittedAt` on the existing Mixed `attestations` object.
- `ERROR_CODES` has no `FREE_LIMIT`. The 429 body uses that code anyway. `docs/contracts/API.md` says the weekly limit is `PAYMENT_REQUIRED` (402). This task follows the brief (429 / `FREE_LIMIT`).
- `DELETE` in API.md returns `{ status: "deleted" }`. The handler returns `{ status: "removed" }` so the public route can answer 410.
- API.md has no resume route. `POST /api/listings/{id}/resume` is implemented because the brief lists resume.
- API.md names only `contact-reveal`. `POST /api/listings/{id}/contact` is the same handler.
- Renew does not debit a wallet. Wallet checkout is T4.1. A renew extends the existing free lifetime by 30 days and does not return `PAYMENT_REQUIRED`.
- `pending -> active` and `pending -> rejected` are legal transitions in the service and have no public route. T7.1 owns the decision API.

## NEED
- `src/proxy.ts` rejects every non-GET without an `Origin` or `Referer`, including `POST /api/cron/expire`. The route itself only checks `x-cron-secret`. A scheduler that sends no origin gets 403 from the proxy before the handler. That file is not a T3.1 path.
