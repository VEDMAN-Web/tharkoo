# H8.51: Categories & fields as one master-detail screen

## Done
- `/admin/categories/` is one screen. Left: ONE list (drag handle, the Home tile picture as a small thumbnail or a dashed empty box, name, ads and "Hidden" in muted text, arrows for the keyboard). "New category" opens a small dialog (Name, Web address that follows the name, Kind). No permanent Add form, no chip row, no old record list.
- Right: the category's name with the "Visible on site" switch and a More menu (View on site, Remove category with a typed confirm; a category with ads is refused and the message says to hide it). Four tabs, the tab and the category are in the address (`?c=<slug>&tab=pictures`), and Back works.
  - Details: two columns on a computer, one on a phone; labels on top, help under the field: Name, Web address, Kind (required), Icon when there is no photo, Max photos for admin posts and imports (blank = 10), SEO intro, and a "Home page" group with the line under the name on the Home tile. A category with no kind shows a red "Choose a kind to save." note at the Kind field (the data is not touched).
  - Pictures: three boxes (Home page tile, Top banner for computers, Top banner for phones, optional), each with a small drawing of where it shows, ONE help line with the size, a big preview at the real crop (3:2, 16:5, 4:5) with click-to-set focus, the picker, and a description field with an example.
  - Form fields (n): the existing fields editor, embedded unchanged in logic. Its switches read On form, Filter and Required on one line; the table header no longer carries a wrong grid role (axe); a category with no fields can now add the first one.
  - Sub-categories (n): the list with arrows, "Add sub-category" and "Edit" in one dialog (Name, Web address, Icon, SEO intro, Visible, Remove with typed confirm).
- ONE sticky save bar for Details and Pictures (Unsaved changes, Discard, Save). Saving shows "Saved. Live on the site in a few seconds." with Undo for pictures, and links to the Home page and to the category.
- On a phone (and a tablet) the list is the page; tapping a row opens the category with an "All categories" Back link.
- The old developer record panel is gone. Checked what the public site still reads: only the category `description` (Home tile line, via `homeBlurb`) is used, so it moved into Details under "Home page". The other fields in that panel (colours, showOnHome, homeCities) are not part of the category model any more and nothing on the new Home reads them.
- The old `/admin/categories/<slug>/` address redirects to the Form fields tab.
- Fixes found on the way: the old screen did not load the saved icon, so a Save could blank it (the new one loads it); a new category and a new sub-category now go to the END of their list (they were order 0); the admin brand link has a name at tablet width (axe).
