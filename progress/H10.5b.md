# H10.5b: the full e2e suite is safe to run with 2 workers, nightly full run, h7-131

Tests and CI only. No test weakened, skipped or deleted. Source files: none changed.

## Done

### 1. Two workers no longer share anything
- Root cause of the 63 failures: with 2 workers both projects (phone-390 and desktop-1440) ran against ONE server and ONE
  in-memory database. Site-wide settings, page layouts, prices, queues, counters, history and the saved admin session are
  shared by nature, so tests that change them collided. Giving each test its own data cannot fix a setting that is global.
- Fix: with more than one worker, each worker starts its own seeded copy of the site (`tests/e2e/worker-server.ts`):
  its own in-memory MongoDB, its own port (E2E_PORT + 1 + worker index), its own copy of the build (so the page cache and
  the uploads folder are private too). `tests/e2e/helpers.ts` wires it in as an automatic worker fixture on `test` and on
  the new `cleanTest` (for the two specs that must not skip the age gate). `baseURL`, `E2E_BASE_URL`, `E2E_MONGO_URI_FILE`
  and `E2E_APP_DIR` point at the worker's own server, so `withLocalDb`, `setRoles` and the like write to the right database.
- With 1 worker nothing changes (the shared server from the config is used). An external server (`E2E_BASE_URL` set) is used as is.
- Run it: `E2E_WORKERS=2 E2E_PORT=4440 npx playwright test` (or `--workers=2`). Build first.
- Also made per-server: the saved admin session file (`.shots/e2e/admin-state-<port>.json`), the uploads folder that two specs
  write into (`uploadsDir()`), the address fallbacks in helpers.

### 2. Nightly full run
- New `.github/workflows/nightly-e2e.yml`: every night (20:30 UTC) and on demand, builds, installs Chromium, runs the FULL suite
  (phone-390 and desktop-1440) with `E2E_WORKERS=2` and `E2E_RETRIES=1` (a test that only passes on the second try is reported
  as flaky), and keeps screenshots and server logs on failure. The ownership check did not block the path.

### 3. Tests that were wrong when another test had run first (fixed in the tests)
- a26-history: seeded rows were 5 to 90 minutes old, the list shows only the newest 200, so a busy database pushed them off. Seeded rows now sit just behind "now".
- a27-ads: the cleared search navigates after a pause and could overwrite the filter picked next; the test now waits for it.
- a8-users: the Staff tab also lists a content editor (made by a5-roles); the role list in the test was missing it.
- h8-55 and a44 (listing layouts): they start from "Not published yet" but another spec may have published a layout first. They now reset the listing layouts first (`resetListingLayouts`).
- h7156-user-edit: ads come back a moment after the account on Undo; the test now waits for them.
- h7-168-plans-hours: stale since H11.1 (#387) raised the longest plan from 48 to 72 hours; the test now checks 72 and the new wording.
- a41-post-builder polluted the next tests: it published a Post-ad layout ("Posting costs {fee} credits to start") and reset the money settings to fixed values (free ads 0) for good, so post-step-5 and h9-2 failed when they ran after it. It now puts the money settings back exactly as it found them, removes the published Post-ad layout, and waits until the standard text is back (the site keeps the live layout for a short while).
- h7-131: see below.

## h7-131 chat flow, "email: invalid input": which side was wrong
- I could NOT reproduce it: it passed alone (both projects), with 2 workers sharing one server (17 passed), and in both full isolated 2-worker runs.
  The failing log of the first 63-failure run was not kept, so the cause below is from reading the code, not from a captured failure.
- The sign-up check is NOT wrong: `registerBodySchema` is `z.email()` and answers "invalid input" only when the email is missing from the request
  (zod: expected string, received undefined); a real address that is malformed answers "Invalid email address".
- So a test posted without an email. In h7-131 the first test sets `shared.sellerEmail`, `shared.slug` and so on, and the others read them. If a later test runs
  without the first (a re-run of one test, a sharded run, or a worker restart), it posts an empty email. That is the test's order dependence.
- Fix on the test side: later tests now stop at once with a clear message ("run this whole file: its first test posts the ad the others use") instead of posting an empty email.
  If it comes back with the whole file running, the log of that run is needed.
