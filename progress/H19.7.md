# H19.7: throwaway email addresses are refused

Done
1. src/server/auth/disposable-email.ts (new): the one list of throwaway domains (yopmail, mailinator, guerrillamail and its siblings, 10minutemail, temp-mail, sharklasers, trashmail, getnada, maildrop and more, about 70) and `isDisposableEmail(address)`. It ignores case and surrounding spaces, and blocks any subdomain of a listed domain by walking up the domain name; a name that merely ends the same (notmailinator.com, my-yopmail.com) is not blocked. No package.
2. Login codes (email-code.ts, sendEmailLoginCode): a throwaway address is refused with "Please use your own email address." before the rate limit, the code and the email: no challenge row, no email.
3. Sign-ups (service.ts, registerUser): the same refusal before the password is hashed and the account made.
4. The message is a Site text key at the end of TEXT_DEFAULTS, `help.email.ownAddress` (Help texts), default exactly as asked; the server uses that default as the error message and as the field message.
Not changed: password login of an account that already exists, policy.ts and every word list.

Tests: tests/server/auth/h19-7-disposable-email.test.ts (11): the list, subdomains, upper case and spaces, normal gmail/outlook/yahoo allowed and look-alike names allowed, non-addresses, the code path (refused, no challenge, no email; a normal address still gets a code), the sign-up path (refused, no account; a normal address still signs up), the text key. No production build was run (server code and text only).
