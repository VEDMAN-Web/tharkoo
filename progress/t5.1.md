# T5.1

## Done

- Flipped `V2` to `""` and `COLL_SUFFIX` to `""`. `modelName("Listing")` is `Listing`. `collectionName("listings", "Listing")` is `listings`. Same for every name in `CLASHING_MODELS`.
- `src/lib/models.ts` is a shim. It re-exports the model values from `@/server/models`, keeps `MODEL_MAP` and `ModelName`, and still exports the old document interfaces (`slug`, `publicId`, `photos`, `variant`, `verified`, `place`, `displayName`, `categorySlug`, `citySlug`, `stateSlug`, `districtSlug`, and the old category/location fields). The shim goes away once T5.2, T7.1, and T7.2 switch their imports.
- `src/lib/queries.ts` reads the unsuffixed models and maps them back to those old field names. Public listing queries use `status: "active"`. Page filters (`categorySlug`, `citySlug`, `stateSlug`, `districtSlug`, `verified`, `photos`) are translated. They are not passed through to `Listing.find`. Contact fields are not returned. `publicView` is the base projection. `variant` comes from the highest active promotion (`super-top` maps to `supertop`). `lastBumpedAt` is `bumpedAt` when the native document has it, otherwise `publishedAt`. Feeds and search sort with `rankScore` / `compareRank`. `getStarListings` is an active `star` promotion. `getFeed` leaves those star rows out so the star strip stays separate. `searchListings` and `GET /api/search` include them. `isThin(count)` is still `count < 3`. Category rows expose `minListingsIndex` (default 3) and `minListingsLocality` (default 10) for a later caller. `listingCountsByCategoryCity` groups active listings by category slug and city slug.
- Locations project `kind` from `type` and `status` from `enabled`. `stateSlug` / `citySlug` walk `parentId`. `getTopCities` follows `TOP_CITY_SLUGS`.
- New reads: `GET /api/search`, `GET /api/categories`, `GET /api/locations`, `GET /api/locations/{id}/children`, `GET /api/locations/resolve`, and an enveloped `GET /api/catalog` (`{ categories, locations }`). An `oldSlugs` hit on resolve is `301` with a `Location` header and `meta.canonicalSlugs`.
- `cached` takes an optional tag list. `invalidateTags` drops those entries. Site, categories, locations, feeds, and counts are tagged.
- Seed inserts 1,500 active demo listings (deterministic `demo-0000` … slugs) plus a seed user `seed@tharkoo.local` and a few active promotion orders. A second run inserts 0 and skips 1500. `npm run seed` calls the v2 seeder. `scripts/patch-photos.ts` is a no-op and no longer imports the legacy schema.
- `scripts/search-p95.ts` inserts 5,000 listings and prints `search_p95_ms`. This run: **9.0** (exit 0, under 150).

## Contracts changed

No edits under `docs/contracts`. Behaviour notes:

- `GET /api/search` `data` is `{ hits, total, facets }`. `facets` is `{ categories: [{ slug, count }], cities: [{ slug, count }] }` for the filtered set before paging. Hits are `publicView` plus `categorySlug`, `stateSlug`, `citySlug`, `districtSlug`, `place`, `publicId`, `photos`, `verified`, `variant`, `lastBumpedAt`, `displayName`. No `contact`, `phone`, `whatsapp`, or `telegram`.
- Query-string `verified=true|1|false|0` is coerced before `searchQuerySchema`. `attributes` is a JSON object. `sort` is `ranked` (default) or `fresh`.
- `GET /api/locations/resolve` takes repeated `slugs` (or one comma-separated value), country then state then city then district then locality. A slug found only in `oldSlugs` returns 301. The current slug returns 200 and `{ chain }`.
- `GET /api/catalog` is now the envelope. It no longer returns raw `{ categories, attributes, packs }`.
- Public GETs use `RATE_LIMITED` / 429 (60 per minute per IP bucket). They do not call `assertOrigin` (the proxy still does).
