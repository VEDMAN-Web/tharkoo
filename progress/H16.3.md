# H16.3: AI draft in the blog editor (Opus #399)

Done
- Content studio > Blog has an "AI draft" button (in the page header; in More on a phone). It opens a drawer: Topic (required), City, Category, Keywords. The server writes a first draft and opens it in the editor.
- The server (src/server/content/studio/ai-draft.ts) calls the Anthropic Messages API with a plain `fetch`. Env NAMES only: `ANTHROPIC_API_KEY` (the key) and `AI_DRAFT_MODEL` (default claude-sonnet-5-5). Values are never printed, stored or put in an audit row. With no key the drawer says "AI drafts need ANTHROPIC_API_KEY on the server" and the button is off; the action answers with the same sentence and makes no call.
- The output is a DRAFT blog post only (title, address made from the title, meta description, short summary, body with H2 sections, FAQ). It is never sent for review and never published. The editor shows the banner "AI draft - check every fact before publishing" until the post is published.
- The prompt: helpful local guide style, no invented numbers, prices, addresses or names (it writes [ADD FACT] instead), no adult or sexual wording, no competitor names, plain text only. A post that still has [ADD FACT] (or a [placeholder ...]) cannot be published.
- Before anything is stored the text is cleaned (tags, links, markdown marks and dashes removed, lengths cut to the editor's limits) and goes through the same word, dash and length checks as any save. If it fails them nothing is saved and the refusal is recorded.
- Role check: content.write. One audit entry per draft (`content.ai_draft`, with role and a summary); a failed or refused try is recorded as `content.ai_draft.failed`. Rate limit: 20 tries a day per staff member (failed tries count); the 21st is refused without a call.
- No new package; no real network call in any test.

Files: src/server/content/studio/ai-draft.ts (new), fields.ts, service.ts, admin.ts, src/server/models/content.ts (one flag, aiDraft), src/app/admin/content/actions.ts, page.tsx, _studio/ContentView.tsx, _studio/Editor.tsx, tests/server/content/h16-3-ai-draft.test.ts, tests/e2e/h16-3-ai-draft.e2e.ts.

Verified: unit tests with the API mocked (11): missing key, role, topic and blocked input, request shape and rules, default and env model, cleaning, [ADD FACT] blocks publishing, publishing clears the banner flag, blocked word in the answer saves nothing, API failure and unreadable answer save nothing and never echo the API text, the 20 a day limit. E2E at 1440 and 390: the button and the drawer, the missing-key message, the banner on an AI draft and none on a normal post. lint, typecheck, forbidden-terms (the prompt avoids the blocked words), webpack build.

Notes: the real service is not called anywhere in this PR; when a key is set on the server the button works as described. Vedant must set ANTHROPIC_API_KEY (and optionally AI_DRAFT_MODEL) on the server himself.
