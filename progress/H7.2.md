# H7.2: one-time code login (relay #63, changed by relay #64)

## Done
- Email login codes, server side (`src/server/auth/email-code.ts`): send and verify, same limits as phone codes
  (3 sends per 10 min per address and per IP, 5 wrong guesses lock the code, a code works once, 10 min expiry).
  An unknown address gets the same answer and no email. A legacy account gets its email marked verified.
  Successful logins and lockouts are written to the audit log.
- Delivery (`src/server/mailer/index.ts`): `deliverLoginCodeEmail` sends through Brevo when `BREVO_API_KEY` is set.
  Off production with no key it logs the code (dev only). In production with no key it refuses, before any lookup.
  `BrevoMailer.deliver` returns false on failure, so a code is never reported as sent when it was not.
- Dashboard warning helper: `loginCodeWarning()` returns "Login codes cannot be sent" in production when no email provider is set.
- Code-only login switch (relay #64): `src/server/auth/code-only.ts`, stored as feature flag `code-only-login`.
  Default OFF (no row). Only a superadmin can change it; each change is audited with before and after.
  When ON: password login, password sign-up and password reset are refused for users and sellers.
  Staff and admin password login is unchanged in both states.
- Routes (`src/app/api/auth/[[...slug]]/route.ts`): `POST email/otp/send`, `POST email/otp/verify`,
  `GET code-only-login` (superadmin), `PUT code-only-login` (superadmin, body `{ enabled }`).
- Sign-in sheet component (`src/components/auth/SignInSheet.tsx`): role choice, mobile or email, 6-digit code,
  30 s resend timer, lockout message, return to `next`. Opens from anywhere with `openSignIn("user" | "seller")`.
  Centred on desktop, bottom sheet under 640 px, reduced motion respected. It is not mounted anywhere yet (see NEED).
