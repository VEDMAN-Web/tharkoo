# H13.1 staff photo and video uploads (part 1: direct upload and the hint)

## Done
- Create ad (/admin/ads/create/), the Media library (upload box and the picture picker) and the bulk import now send the file straight to Cloudinary with a signed request, like the seller post-ad flow: the browser asks `POST /api/media/staff-sign`, sends the file to Cloudinary, then `POST /api/media/staff-complete`. Our server never receives the file bytes, so the host's 4.5 MB request limit no longer applies.
- Sign checks: a signed-in staff session (403 for a member, and for a staff role without the permission: an admin for create ad and import; someone who may edit the site for the Media library), the owner account (ownerEmail logic kept), the type and size rules (8 MB photo, 10 MB and 30 s ad video), and the people rule (no video when the chosen category is a people category). Complete checks the slot was signed for that staff member and screen, looks at what Cloudinary really holds (type, size, length), scans it, destroys it when it breaks a rule, and records it: audit rows (media.staff_sign, media.admin_upload or media.import.upload with the staff member and the owner), the watermark transformation is part of the signed upload as before.
- The old routes (/admin/ads/photos/, /admin/media/upload/, /admin/import/files/) stay for local development (no Cloudinary: the sign answers "legacy") and refuse files over 4 MB with the plain sentence. Nothing else calls them.
- A refusal that is not ours (host error page, dropped connection) shows "This file could not be uploaded (too big or a network problem). Try a smaller photo." Our own refusals show their plain sentence. "Connection problem" is gone from these screens.
- Create ad: "Pick a category first, then add photos." beside the disabled Photos picker.
- Size and type limits are unchanged (the shrink of big photos is part 2).
