# H3.6 — Post-ad page blocks and category field editor

## Done
- `src/components/post/copy.ts`: `buildPostCopy(blocks)` turns the published `post/default` blocks into the plain wording object the wizard shows (steps, photo rules, promotion note and products, success text, intro, whether the promote step is hidden). `wizardFields()` gives a category's fields in the admin's order without switched-off ones.
- `src/server/layout/defaults/post.ts`: `postDefaultBlocks()` (intro, six steps, photo rules, promotion picker, success) with today's wording; `seedPostLayout()` publishes it as `post/default` v1 (idempotent, also run by `seedLayouts()` and the first time an admin opens the post editor via `loadLayout`).
- `PostWizard` takes an optional `copy`; with no layout it shows exactly the old strings. `src/app/u/post-insert/page.tsx` reads the blocks (try/catch, falls back to the built-in wording). Posting logic, validation, KYC gate and payments untouched. Hidden promote step: the Plan panel is simply not shown.
- Category post-fields editor: `/admin/categories/` now lists every category; `/admin/categories/<slug>/` edits each field's label, help text, placeholder, required flag, order (SortableList) and options (select/multiselect). Server: `fields-service.ts` validates with the existing `fieldDefinitionListSchema`, runs `textDenied` on every string, admin/superadmin only, writes audit event `category.fields.update` (before and after). Fields cannot be added, removed or change type here.
- The wizard shows each field's help text and placeholder and follows the admin's order.
