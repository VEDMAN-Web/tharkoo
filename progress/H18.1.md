# H18.1: PassimPay crypto checkout for credit packs

Done
1. src/server/billing/passimpay.ts (new): `signBody` (hex HMAC-SHA256, key = API key, message `platformId;body;key`), `createInvoice` (POST createorder: platformId, orderId, amount with 2 decimals, symbol INR, type 1), `orderStatus` (POST orderstatus), `verifyWebhookSignature` (over the body as received, else over the re-serialised JSON; says which form matched), `passimpayConfig`. Plain fetch, 10 s timeout, one serialisation that is both signed and sent. Every failure (network, timeout, refusal, bad answer) is `InternalError("Payment provider is not available")`. The key and any signature are never logged, stored, audited or put in an error.
2. checkoutPack (service.ts): with PAYMENT_PROVIDER=passimpay the Payment is created first, its id is the order id and is saved as providerRef BEFORE the invoice is opened, createInvoice is awaited, and the buyer gets `checkoutUrl`. If the invoice cannot be opened the Payment is deleted (as before). ALLOW_LIVE_PAYMENTS=true and both keys are required before any Payment is written. A repeat of the same idempotency key on a PassimPay payment answers "already open" instead of sending the buyer to the test page. Mock and Razorpay paths unchanged.
3. Webhook, src/app/api/payments/passimpay/webhook/route.ts: refuses bodies over 8 KB (413); verifies x-signature (a refusal is recorded by reason only and answered 400); a valid webhook only names the order. src/server/billing/passimpay-events.ts `confirmPassimpayOrder` then asks PassimPay's orderstatus: only "paid" credits, through the existing applyWebhook (eventId `passimpay:<orderId>`), so idempotency, audit and ledger stay one path; "wait" does nothing (200); "error" marks it failed; INR amountPaid must cover the price, and a paid answer with no currency credits nothing (ConflictError); an unknown order is a 200 no-op. The webhook body alone never credits. A delivery that cannot confirm the credit answers an error so PassimPay retries.
4. applyWebhook now refuses to touch a PassimPay payment unless the PassimPay confirmation set `confirmedBy: "passimpay"`: the generic signed webhook (PAYMENT_WEBHOOK_SECRET) can no longer credit or fail a PassimPay payment (security review finding).
5. Return page, /u/account/credits/?payment=success: the buyer's newest pending PassimPay payment is checked with the same function (a lost webhook still credits; a provider that is down never breaks the page, the reason is audited). Two Site text lines (`recharge.return.success`, `recharge.return.failed`) show for ?payment=success and ?payment=failed.
6. UI: the credits pack picker, when the provider is PassimPay, has no card or coin choice (the buyer picks the coin on PassimPay's page) and the button says "Pay with crypto" (`recharge.payCrypto`, Site text); it goes to the returned checkout url (the existing checkoutPath redirect). startRecharge forces method crypto and returns the PassimPay url as checkoutPath. The /api/payments/packs answer says `provider` and `available` (PassimPay needs live payments allowed and both keys). Admin orders show "Real payment (PassimPay)".
Env NAMES only: PASSIMPAY_PLATFORM_ID, PASSIMPAY_API_KEY, PAYMENT_PROVIDER=passimpay (and ALLOW_LIVE_PAYMENTS=true, as before). No value is in the code, tests, logs or this note.

Tests (tests/server/billing/h18-1-passimpay.test.ts, 25, fetch mocked, fake key "test-key", platform 123; any call to another URL throws): signature test vector; createInvoice sends exactly the string it signed; bad answers are one plain error; checkout creates the Payment first and returns the url, deletes it when the provider is down, makes no order unless live payments are allowed, mock path unchanged; webhook: bad or missing signature 400 with an audit row that holds no value, good signature plus paid credits once, same webhook twice once, wait not credited, lower INR amount not credited, error marks failed, unknown order 200 no-op with no provider call, re-serialised body accepted; return page credits once and never throws; review fixes (generic webhook cannot credit, no currency, large body, same-key repeat, order id saved first).
