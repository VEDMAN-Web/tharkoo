# T2.3

## Done
- Manual admin approval only. `KYC_PROVIDER` unset or `manual` is the only path. Any other value returns `INTERNAL`. No vendor SDK and no vendor provider interface.
- User routes: `POST /api/verification/id/upload-url` signs a T2.2 `id_document` upload (`{ uploadUrl, assetId }`), `POST /api/verification/id/complete` stores that asset id and returns `{ status: "pending_review" }`, `GET /api/verification/status` returns the caller's `{ status, reason? }`.
- A second complete while `pending_review` is `409 CONFLICT`. A complete after `rejected` is allowed and opens a new row. An already `approved` user cannot submit again.
- Admin routes for `superadmin`, `admin`, `trust_safety`, and `moderator`: `GET /api/admin/verifications` is the pending queue, oldest first; `POST /api/admin/verifications/{id}/decision` approves or rejects; `GET /api/admin/verifications/{id}/file` returns `signedIdDocumentUrl` (120 seconds, authenticated, not a public delivery URL). Role `user` is `403` on all three.
- Approve and reject append `verification.decision` with the actor, the decision, and the reason. A decision without a reason is `400 VALIDATION_ERROR` and writes no audit row. Each file view appends `verification.view`.
- `assertVerified(userId)` throws `VERIFICATION_REQUIRED` unless `users.verificationStatus` is `approved`.
- Status names follow the contract: `unsubmitted` (the brief's "none"), `pending_review` (the brief's "pending"), `approved`, `rejected`.

## Not done
- NEED: `IdentityVerification` has one `documentRef` string, and `verificationCompleteBodySchema` accepts one `assetId` (max 64). Front, optional back, and selfie cannot be stored as separate fields without a model and schema change. This task stores the one submitted `id_document` asset id in `documentRef`.
- NEED: `identity_verifications` has no `{ status, createdAt }` index. The queue sorts by `createdAt`. The model was not edited.
- No verification UI. T2.4 and T7.2 own those screens.
- `support`, `seo_editor`, and `finance` stay staff for other admin routes and are not review roles here.

## API changes
- No edits to `docs/contracts/API.md`.
- A second submit while pending, and a submit after approval, return `CONFLICT`. The complete row does not list that code.
- A missing session on an admin verification route is `UNAUTHORIZED`. The file row lists `FORBIDDEN` and `NOT_FOUND`.
- Reject (and approve) without a reason is `VALIDATION_ERROR`. The decision schema already requires `reason`.
