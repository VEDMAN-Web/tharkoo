# H5.1 - end-to-end test harness (lane D)

## Done
- `playwright.config.ts`: suite in `tests/e2e`, two projects (phone 390x844, desktop 1440x900), one worker.
  Starts `tests/e2e/server.mjs` (production build, in-memory Mongo, seeded) on port 4342 unless `E2E_BASE_URL` is set.
- `tests/e2e/server.mjs`: local-only server; writes the in-memory Mongo URI to `.shots/e2e/mongo-uri.txt` so the role tests can promote a test account.
- Journeys (each runs at 390 and 1440): 1 Visitor, 2 Search, 3 Account, 4 Advertiser, 5 Money (mock provider, confirmed through the signed webhook), 8 Roles.
- Plus: axe (home, listing, ad, register, admin dashboard), overflow at 390/768/1440 on 20 public pages, security sweep (no contact values in HTML/RSC/JSON, admin noindex, Origin check on POSTs, no secrets in `.next/static`).
- Bug list: `.relay/lane-d-bugs.txt` in the main checkout. Known bugs are `test.fixme` so the suite stays green.

## How to run
```
npm run build
npm run test:e2e              # starts tests/e2e/server.mjs itself
# or, with a server you started: E2E_BASE_URL=http://127.0.0.1:4342 npm run test:e2e
```
On this PC set `TEMP`/`TMP` to a drive with space (in-memory Mongo needs temp space).

## Risks
- The advertiser and TOP tests wait up to about 100 s on desktop because city feeds are cached for 60 s (BUG 4).
- The suite registers many accounts. Registration is limited to 20 per address per 15 minutes, so each test sends its own `X-Forwarded-For`. The admin login is limited to 5 per 15 minutes, so the admin session is saved in `.shots/e2e/admin-state.json`.
- Role tests promote an account by writing to the in-memory test database only (refuses any non-local URI).
