# H6.3 Videos on ads ("reels")

Branch: haiku/h6.3-videos (based on haiku/h6.0-ownership because PR #95 was not merged when this started)

## Done
- Advertiser can upload up to 2 videos per ad in the post/edit form (`VideoUploader`, next to the photos). mp4, webm, mov; max 10 MB; max 30 seconds. The line "Videos: up to 2, max 10 MB and 30 seconds each." is shown under the button.
- Checked on the client (type, size, length read from the file) and on the server:
  - sign step: type, declared size, ad owner, limit of 2 per ad;
  - local storage: real bytes (size, mp4/mov `mvhd` and webm duration parsed in `src/server/media/duration.ts`);
  - Cloudinary: size, format and duration reported by Cloudinary on `complete`; a bad file is destroyed.
- Storage uses the H3.11c adapter (`src/server/media`): Cloudinary `video/upload` when the three env names are set, else `public/uploads` (tests use this local path). Cloudinary poster = first frame via URL (`so_0,f_jpg`); local storage has no poster.
- Videos are NOT added to `Listing.mediaIds`, so photo logic is untouched. They are read as `MediaAsset` rows with `kind: "video"`, `status: "cleared"`.
- Ad page: `AdVideos` strip under the ad (muted, playsinline, loop, plays only while >= 50% on screen via IntersectionObserver, paused off screen, no autoplay on Save-Data or prefers-reduced-motion where native controls are shown instead, `preload="none"` + poster so LCP is not affected). Component `ReelVideo` is reusable for cards.
- No moderation queue: videos go live once the size/length/CSAM-stub checks pass.
- Safety net: Report form has a "A video on this ad" reason (`REPORT_REASONS` includes `video`). Video reports go to a `VideoReport` collection (`src/server/reports/video-report.ts`). 3 or more open reports from different reporters hide the ad's videos until an admin reviews. Admin > Media library has an "Ad videos" panel: remove a single video (file deleted, reports closed, audit `video.remove`) or "Keep and clear reports" (audit `video.reports_dismissed`).
