# T2.1

## Done
- Account routes under `/api/auth`: register (date of birth + 18+ attestation), verify email, login, logout, me, forgot password, reset password, session list, revoke one session, phone start/confirm.
- Session cookie `sid`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` when `NODE_ENV=production`. The value is a random token. Only its hash is stored (`SESSION_SECRET` HMACs it when set).
- Login rotates the presented session (that cookie stops working) and leaves other devices signed in. Logout revokes the current session. Password reset revokes every session for that user.
- Login lockout is 5 attempts per email per 15 minutes. The sixth returns `429` with `Retry-After`. The counter is a Mongo document (`auth_rate_limits`) with a TTL index, so a process reload keeps the window. `src/proxy.ts` uses the same limiter when `MONGODB_URI` is set, and the previous in-memory limiter when it is not.
- Mutations require an `Origin` or `Referer` that matches `SITE_URL`, `NEXT_PUBLIC_SITE_URL`, the request host, or (outside production) `http://127.0.0.1:4317` / `http://localhost:4317`. The proxy applies the same check.
- Staff gate in `src/lib/admin-auth.ts` reads the session cookie. Role `user` gets 403 on `/api/admin/list`. Staff roles: `admin`, `superadmin`, `moderator`, `trust_safety`, `support`, `seo_editor`, `finance`. `cursor/**` is deleted. Nothing under `src` imports it.
- `ADMIN_BOOTSTRAP_EMAIL` + `ADMIN_BOOTSTRAP_PASSWORD` create one verified `superadmin` on the first login attempt. A second call does nothing. The audit row does not contain the password.
- Brevo mailer (`BREVO_API_KEY`, sender env vars). No key: console transport, and the body is logged only outside production. Phone OTP runs outside production, or in production when the `phone-otp` flag is enabled. The code is written to the server log. The JSON includes `dev: true` only outside production.
