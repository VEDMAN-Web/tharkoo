# H5.9b: dash repair follow-up (relay #43)

## Done
- Daily cron (`src/app/api/cron/expire/route.ts`) now runs `repairDashes` and a new `repairDemoListingDashes` on every run. The response keeps its shape and adds `dashesUpdated` and `demoListingDashesUpdated`.
- Demo ads: `repairDemoListingDashes` (`src/server/content/dash-repair.ts`) fixes the title and description of listings owned by the seed user (`SEED_USER_EMAIL`). The Listing model has no demo flag and this change adds no field, so ownership by the seed user is the marker (the same rule `refresh-demo-ads.ts` uses). Real listings are never read or written. The seed run (`src/server/seed/run.ts`) calls it too.
- Admin: new screen at `/admin/seo/tools/` with a "Fix long dashes" button that shows the counts returned. The server action (`src/app/admin/seo/tools/actions.ts`) checks for superadmin before it runs `repairDashes`. Only stored content is repaired there, not listings. Nav entry "Tools" under SEO (minRole seo_editor) and a Tools tab in the SEO centre.
- Seed titles: the seed source (`src/server/seed`, `src/content`, `src/data`) and the demo listings already contain no em or en dash. A scan of src, tests, scripts and .github found none in code. No seed file needed a change.
- Tests in `tests/server/content/dashes.test.ts`: demo repair touches only the seed user's ads (a real ad with a dash is unchanged), a second run changes nothing, the cron run includes both repairs, the button refuses a non-superadmin and runs for a superadmin, and the seed data and source files contain no dash.
