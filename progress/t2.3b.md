# T2.3b

## Done
- `POST /api/verification/id/complete` accepts only `{ frontAssetId, backAssetId?, selfieAssetId }`. `frontAssetId` and `selfieAssetId` must be different. A repeated id is `400 VALIDATION_ERROR` and writes no verification row.
- Each id must be the caller's own `id_document` asset. A missing or unknown id is `400`. Someone else's asset, or an asset that is not an `id_document`, is `403`.
- The row stores `documents.front`, `documents.back` when sent, and `documents.selfie`, and sets legacy `documentRef` to the front id.
- `GET /api/admin/verifications/{id}/file` returns signed 120s URLs for front, back (when stored), and selfie. One `verification.view` audit row is written per view.

## Not done
- No verification UI. T2.4 and T7.2 own those screens.
- `documents` is optional on old rows that only have `documentRef`. New completes always set it.

## API changes
- Complete body is `frontAssetId`, optional `backAssetId`, and `selfieAssetId`. The file response is `{ front, back?, selfie }`, each `{ url, expiresAt }`.
- Model and contract edits are in this same commit. Ownership for those paths is the `T2.3b` entry on `cursor/t0.1-ownership-t2.3b`.
