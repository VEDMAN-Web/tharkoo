# H10.5c (Lane B): h9-1 "Account home and the Wallet show the same picker" and contact-card H6.8 "signed-in visitor without coins is told by the server"

Root cause first. In both cases the product is right and the tests shared state with another worker or relied on a race.

## h9-1 credit packs: "the Account home and the Wallet show the same picker"
- Evidence before: on current main the spec passes alone. It fails as soon as paid posting is on (another spec, for example the recharge-flow or money specs, sets it on in the shared test database while two workers run): `[data-tk="pack-ads"]` count Expected 0, Received 4. Reproduced on purpose by switching paid posting on in the database and running the spec: 1 failed, 1 passed.
- Cause: the spec assumed posting is free and asserted that no "Enough for ..." line shows. Since H11.1b that line shows by design while posting costs credits.
- Fix (test only): `checkPicker` reads `prices.paidPostingOn` from the same answer the picker uses and asserts accordingly: no line while posting is free, an "Enough for ..." line on every pack while it costs credits. No assertion was weakened: the old check is still made when posting is free.
- Evidence after: with paid posting switched on, the spec passes.

## contact-card H6.8 "a signed-in visitor without coins is told by the server, and no request is sent" (phone), and the chat round trip (desktop)
- Evidence before (main, 2 workers): phone failed with `Received ["http://127.0.0.1:4410/api/tours/request/"]` (a tour request was sent), desktop failed with "waiting for [data-tk=contact-card] [data-tk=tour]". Alone, the same tests passed three times in a row.
- Cause 1 (phone): the call popup asks for the balance when it opens. The button sends a tour request when the balance has not arrived yet, and goes straight to "buy" when it knows the balance is 0. Both are correct (the server answers 402 and nothing is held), but the spec clicked at once, so it raced the balance answer. Fix: wait until the balance tile no longer shows "…" before clicking. The assertion "no request is sent" is unchanged.
- Cause 2 (desktop): the chat round trip moved the ownership of the shared first property ad to another account for the length of the test, while the other project (phone or desktop, on the other worker) used the same ad for the tour button, so the tour button disappeared. Fix: the round trip now makes its own ad (a copy of the first one, owned by the advertiser) and deletes it afterwards, so no shared ad is ever changed.
- Evidence after: both specs on 2 workers, three runs in a row: run 1: 19 passed, 3 skipped, 0 failed; run 2 (with paid posting switched on): 19 passed, 3 skipped, 0 failed; run 3: 19 passed, 3 skipped, 0 failed.
