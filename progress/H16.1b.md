# H16.1b: admin "Import cities and areas (CSV)" with preview and Undo (part 2 of H16.1)

Builds on H16.1a (the data files and the CSV reader). Part 3 (H16.1c) is the location pickers.

## What it does
Admin > Cities & areas has a new button "Import cities and areas (CSV)". The dialog offers three sources: the built-in list of cities, the built-in list of areas, or a CSV file of the admin's own (cities: name, state, slug; areas: city, name, slug).
1. Preview reads the file and sorts every row into new, already there, or a problem (with the line, the name and the reason). It writes nothing.
2. Import adds only the new rows. Rows with a problem are skipped. Places that are already there are not renamed, hidden, moved or removed. New cities get the Order number after the cities already there, so they list by name behind them. New areas are added as districts of their city.
3. ONE audit entry for the whole import ("Imported 842 cities (45 already there, 3 skipped)"), with the actor's role. It can be undone from the dialog or from History & undo for 30 days. Undo removes exactly the places that import added; if one of them has meanwhile got an ad or a place inside it, Undo of the whole is refused with a plain message (hide that place instead).
4. Checks: the catalogue.edit permission on preview and on import (server side), names cleaned and tested against the forbidden terms (a name that is not allowed becomes a problem row and is skipped), web addresses checked with the site's own slug rules and required to be in the tidy form, a web address that another city already uses (also an old address) or that is a category address is a problem.
5. The built-in lists are read from `data/locations/`; `next.config.ts` now traces them into the standalone build (`outputFileTracingIncludes` for `/admin/locations`), and a build was checked: `.next/standalone/data/locations/india-cities.csv` is there.
6. The import is never run on the live database by this PR. After merge, an admin presses Import on the live admin.
