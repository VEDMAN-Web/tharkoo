# H7.2b: no-password accounts, seller profile, admin switch and sign-in sheet e2e (relay #66)

## Done
- No password for users and sellers (`src/server/models/identity.ts`). `passwordHash`, `dateOfBirth` and `attestedAdultAt` are required only for staff roles (`STAFF_ROLE_NAMES`). Staff sign-in is unchanged.
- Sign-up by code (`src/server/auth/email-code.ts`): a code now goes to any valid address, so a new address signs up by proving it. The first correct code creates a passwordless account (`createCodeAccount` in `service.ts`) and logs in. The response is the same for known and new addresses.
- Password login cannot match a passwordless account. `loginUser` compares against a dummy hash when there is no stored hash, so the placeholder text does not sign in.
- Seller profile (`src/server/auth/seller-profile.ts`, route `PUT /api/auth/seller-profile`): name (2-60), city (2-60), optional WhatsApp (8-15 digits), "Available now". Date of birth and the 18+ tick are taken only while the account has no date of birth, so they are asked once. Under 18 is refused and nothing is written. Date of birth is never returned to the browser.
- Post your ad (`src/app/u/post-insert/page.tsx`): with New design on, a logged-in account with no seller profile goes to `/u/seller-profile/?next=...` first. A signed-out visitor goes to login with `role=seller`.
- Sign-in landing (`src/components/auth/landing.ts`, pure and tested): staff to admin; a returning seller to the seller panel; a new seller to the profile step, then the ad form; a user to the user panel (`/u/account/saved/`). A same-origin return address wins, except that a new seller still does the profile first.
- Sign-in sheet mounted on `/u/login` (`src/app/u/login/page.tsx`) behind the New design switch. Off, the old password form stays. Email is the default channel. The mobile tab shows only when an SMS gateway can deliver (`smsDeliverable()` is false until one is built).
- Admin: dashboard warning "Login codes cannot be sent" (`loginCodeWarning()`, now false only when email or SMS can deliver). Superadmin-only "Code-only login" switch (`src/components/auth/CodeOnlyLoginSwitch.tsx`, server action `code-only-actions.ts`). Turning it on is refused while no code can be sent.
- E2e: `tests/e2e/login-sheet.e2e.ts`, runs at 390 and 1440. It covers the sheet (no password field, axe, no sideways scroll), the no-mail message, new seller sign-up through the profile to the ad form, new user to the user panel, and five wrong codes locking the right one. The mock provider answers the send step; the test seeds the code hash the server would store.

## Not done
- SMS sign-in and sign-up: the SMS gateway is still not built (`smsOtp` throws). The mobile tab stays hidden until it is.
- The "Welcome / add a name" step from the mockup (name is taken in the seller profile instead).
- Header "Log in" and "Post your ad" buttons calling `openSignIn`: those are H7.1 files.
- Brevo is not set up. Code-only stays OFF on production until Opus confirms it.
