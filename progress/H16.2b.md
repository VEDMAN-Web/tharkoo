# H16.2b: every link to an ad uses its new address (PR 2 of 3)

Branch: `haiku/h16.2b-link-builders`, on top of main with PR 1 (#450).

## Done

- `adHref(paths, ad)` in `src/lib/urls.ts`: the ad's own address when the row has one, else the old `/ad/<slug>/` link (which forwards).
- Presented rows (`presentRows`: cards, rows, pop-outs, hits) carry `address`. Cards, home cards, related ads, JSON-LD item lists, chat Inbox and chat service, My media, seller dashboard, analytics panel, admin "view on site", the post-ad "view your ad" link (API `by-id` returns `address`), IndexNow and cache-purge paths (`publicPathsOf`, `listingPagePaths` also purges the address), admin SEO table pattern.
- Report link uses `?ad=<code>`; the report API and the takedown form accept the ad code (or a pasted address).
- `data-ad-link` on every anchor that points to an ad, so specs no longer depend on `/ad/` in the link; about 14 existing specs and `helpers.ts` use it (`firstAdPath` still returns the old `/ad/<slug>/` form through a database lookup so specs that think in slugs keep working).

## Not done

- 50-page crawl found or fixed nothing outside what is listed; see the crawl spec below.
- Sitemaps were done in PR 1.

## Tests

- Unit: `tests/server/listings/h16-2b-links.test.ts` (adHref, address on presented rows, addresses for lists, public paths, report by code, address code reader).
- e2e: `h16-2b-links.e2e.ts` (every card, row and related link is the new address; report link carries the code), `h16-2b-crawl.e2e.ts` (50 pages, every internal link opens, no link points at an old `/ad/` address).

## Risks

- Ads that have no code yet (older ads) keep the old link, which forwards; the cron backfill fills codes.
