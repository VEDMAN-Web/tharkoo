# H6.1 Countries and cities in admin, plus the footer

Branch: haiku/h6.1-locations (based on haiku/h6.0-ownership, because PR #95 was not merged yet).

## Done
- Admin > Locations: new screen to add, edit, hide and remove countries, states and cities (name, slug, flag code, order, shown/hidden). Slug changes go through the existing rename (old address redirects). Removal is blocked when the place has children or ads (hide instead). Server-side admin role check, name checked against forbidden terms, audit log entry on every write.
- Footer "Countries" block: flag, name, live ad count, expands to cities. Only places with at least 1 active (unexpired) ad, at most 12 countries, busiest first. "All countries" link to /countries/. Links go to the existing hub URL (/{first category}/{place}/).
- New page /countries/: every enabled country with its cities and counts, one h1.
- Indexing rules are untouched (hub pages and sitemap not changed).

## Not done / NEED
- NEED: a stored `flag` field would need src/server/models/catalog.ts (not in the H6.1 globs). The flag is derived from the country's two-letter `countryCode` instead.
- NEED: src/components/PathChrome.tsx, src/app/sitemap/** and src/lib/urls.ts RESERVED are not in the globs. The footer block therefore loads its own data through a server action (src/server/locations/footer-action.ts) so PathChrome did not need to change. /countries/ is not added to the sitemap (it is a directory page).
