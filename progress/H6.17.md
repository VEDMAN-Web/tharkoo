# H6.17: card width and views and clicks on ads (relay #59, lane G)

## Done
- Card width: Admin > Listing pages > "Card width" (Narrow 760 px, Medium 880 px default, Full width). Stored on the Site doc as `listingCardWidth`, audited (`listing_pages.card_width.update`, before and after). Category and city pages set `data-card-width`; CSS caps `.tk-feed` at 760 or 880 px. Phones are unchanged.
- Views and clicks on every ad card (bottom right, muted, 12 px, lakh grouping) and on the ad page under the detail block.
  - View: card at least 50 percent on screen for 1 second (listing, home, search), or the ad page opened. Sent once per page; the server decides once per visitor.
  - Click: the card's own link. Sent at once with sendBeacon, so it survives navigation.
  - Batches go to `POST /api/views/` (sendBeacon, max 50 events per batch, rate limit 120 batches per minute per IP, origin check, bots and staff and owner and non-active ads not counted).
  - Live: `GET /api/views/counts/?slugs=` returns shown counts for visible cards only (15 s server cache). Cards refresh every 30 s while the tab is visible.
- Visitor: signed-in user id, otherwise a random first-party cookie `tk_vid` (one year, HttpOnly). Stored only as an HMAC (`visitorKey`); no IP, no raw cookie or user id in event rows.
- Dedupe: `AdEvent` collection with unique index `{listingId, visitorKey, type}`. A counter is incremented only when that insert succeeds, so concurrent requests cannot double count.
- Real counts: `AdCounter` collection with `realViews` and `realClicks`. Kept out of the Listing document, which the generic admin Listing editor writes as a whole record.
- Admin > All ads: `/admin/ads` lists the 50 most recent ads with shown and real counts. `/admin/ads/[id]` is "Views and clicks": two number fields (shown views, shown clicks), real counts beside them, admin and superadmin only, audited with before and after.
- Shown value = set number + real count - real count at the moment of the set. Visitors counted before a change are not counted again.
- CSS fix found by e2e: `.tk-card-body .tk-trust` now wraps. Before, three nowrap trust chips made each phone card 528 px wide at a 390 px viewport (pre-existing layout bug).

## Not done
- Advertiser statistics, promotion reports and dashboard do not show views yet. There is no existing screen that shows views. `realCountsFor()` in `src/server/analytics/counts.ts` is ready for them.
- Click is counted when the card link is clicked, not when the ad page loads. Ctrl-click (new tab) also counts.
- Ad-page counts sit below the detail block, not in the title area (`AdDetail.tsx` is outside this lane's globs).
- Admin "All ads" shows only the 50 most recent ads; there is no search.

## Risks
- Real counts are kept in `AdCounter`, not on Listing. Listing exports and reports must read them from there.
- The visitor cookie is set by the `POST /api/views/` response. If a browser drops it, each event counts as a new visitor.
- Shown counts are cached for 15 s on the server, so a fresh admin save may take up to 15 s to show on cards.
