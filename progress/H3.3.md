# H3.3 — Media library

## Done
- `src/server/layout/media.ts`: `uploadSiteMedia`, `listSiteMedia`, `updateSiteMedia`, `deleteSiteMedia`, `findUsages`, `readImageSize`. Admin or superadmin only. Types: jpeg, png, webp only (no SVG), up to 5 MB; the declared type must match the real file header (width and height are read from it); alt text required (3 to 125 characters) and checked against the forbidden-terms list, as are tags (at most 10). Every write is audited (`media.site.upload`, `.update`, `.delete`).
- Files are written like listing photos (24 hex characters, `public/uploads/<id>.<ext>`), so the existing `/uploads/[file]` route serves them straight away. `SITE_MEDIA_DIR` overrides the folder (tests).
- Delete is refused while any draft or published block uses the image, and the message says where ("home page, draft"). Filters: search by alt or tag, **Images missing alt**, **Oversize** (over 500 KB), **Unused**.
- `src/app/admin/media/`: page, `MediaLibrary` (upload form, filters, cards with inline alt/tags edit and a type-to-confirm delete), server actions for list/update/delete, and `upload/route.ts` for the upload itself (server actions cap the body at 1 MB). The route checks the origin and the staff role.
- `src/components/admin/ui/ImagePicker.tsx`: modal to pick an existing image or upload a new one (alt required); returns `{ assetId, src, alt, width, height }`, the shape blocks store.
- Sidebar: "Media library" now links to the real page (`nav.ts`); `admin-nav.test.ts` no longer depends on one specific unbuilt item, so later parts can flip their own item.
