# H7.103 recharge sheet, mock checkout and purchase history

## For Lane B: open the recharge sheet
```ts
import { openRecharge } from "@/components/recharge/openRecharge";

openRecharge({ shortfall: 18 });
openRecharge({ shortfall: 18, returnTo: "/u/post-insert/?step=5" });
```
- `shortfall` (credits, optional): the sheet shows "You need 18 more credits to publish." and pre-selects the smallest pack that covers it.
- `returnTo` (same-origin path, optional): where the browser goes after the payment. Default: the page that opened the sheet (path and query).
- The sheet is mounted once for the whole site (inside the New design shell), so the call works from any page. Signed-out visitors see a log in link.
- After the payment the page comes back with `?recharge=paid&credits=N&payment=ID` or `?recharge=failed&payment=ID`. The shell removes those parameters, shows the toast ("N credits added", or "Payment was not completed. Nothing was charged." with Try again and Contact support) and refreshes the server data on success. To update a balance you show yourself after success, refetch `GET /api/wallet/posting-fee`.

## What exists
- Sheet: centred modal on desktop (max 560 px, fits 1536x674 without scroll), bottom sheet on phones. Up to 6 packs sorted by size (the pack that covers the shortfall is always among them), Most popular / Best value badges from the admin tag, "+N bonus". Card (Visa, Mastercard) or Crypto (Bitcoin, Ethereum, USDT, USDC). Footer: Contact support opens the chat with pack, amount and method filled in, and a Secure payment line.
- Pay pages: `/pay/checkout/{paymentId}/` (owner only). Card: merchant, amount, Test payment ribbon, Pay / Cancel, 2 second Processing, redirect back. Crypto: choose coin (BTC, ETH, USDT, USDC), network for USDT and USDC (TRC-20, ERC-20, BEP-20), estimate in the coin, test deposit address with copy and a test QR, 30 minute timer, I have paid, Waiting for confirmation, success; cancel and expired states. No card number field anywhere.
- API (signed in): `GET /api/payments/packs?shortfall=N`, `POST /api/payments/recharge {packId, method, returnTo}`, `POST /api/payments/{id}/coin {coin, network}`, `POST /api/payments/{id}/confirm {outcome: paid|cancelled}`, `GET /api/payments/{id}` (receipt), `GET /api/payments/history`.
- Credits arrive only through the existing payment path: the page calls `confirm`, which checks the payment belongs to the signed-in user, is a pending mock payment and "Mock payments" is On, then runs the same `applyWebhook` code the signed provider webhook uses. They land in the WalletEntry wallet (the header pill). With Mock payments Off (and no real gateway) the sheet says "Payments are not available right now" and no payment can start or be confirmed.
- History: `/u/account/credits/history/` lists every purchase (method, amount, credits, status) with a receipt page `/u/account/credits/receipt/{id}/`.
- The header credits pill and the credits page button open the sheet.

## Notes
- The test QR is a drawn pattern, not a real QR code (no QR library is installed); it is labelled as a test.
- Crypto estimates use fixed test rates (BTC Rs 55 lakh, ETH Rs 2.8 lakh, USDT and USDC Rs 88).
- Tours (video calls) still debit the coin ledger, a different wallet (see progress/H7.102.md).
