# H6.2 Categories and sub-categories

Status: PARTIAL. Everything inside the H6.2 ownership globs is built and tested. The pieces that live in files outside the globs are listed under NEED.

## Done
- New `Subcategory` model (`src/server/models/subcategory.ts`): category, slug, old slugs, name, icon, order, visible, SEO intro.
- Admin service `src/server/categories/manage.ts`: create, edit, hide, delete and drag-reorder for categories and sub-categories. Admin role check, name/intro checked against the content policy, audit entry on every write. Deleting a category or sub-category that has ads is blocked with "Hide it instead". A slug change keeps the old address redirecting.
- Admin screen `/admin/categories/` now has a manager (drag or arrow reorder, add, edit, visible toggle, remove with typed confirm) using the admin UI kit.
- Post form: when the chosen category has visible sub-categories, a required "Select sub-category" field appears (same step as the category). `subcategoryId` is sent in the basics save, accepted by the API schema (`src/server/shared/schemas/listings.ts`) and loaded back from a saved draft.
- Public page `/{category}/{city}/{sub}/` (served by the existing district route when the last part is not a district). Indexable only with 5 or more real active ads on page 1, otherwise noindex. Old sub-category slugs redirect permanently.
- Sub-category chips with live counts on category pages (link to the city with most ads) and city pages (`SubcategoryChips`).
- Helpers ready for the other files: `resolveSubcategory` (CSV), `indexableSubcategoryHubs` (sitemap), `subcategoryChips`.
- Tests: `tests/server/categories/subcategories.test.ts` (15 cases).
