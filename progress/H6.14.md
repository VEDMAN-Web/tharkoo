# H6.14: "Require ID check before posting" switch (default OFF)

## Done
- **Switch.** Superadmin-only, audited setting "Require ID check before posting" on Admin > Settings (`src/app/admin/settings/IdCheckSwitch.tsx`), saved through `PUT /api/admin/settings/id-check` (`src/app/api/admin/settings/id-check/route.ts`). Stored on the site document as `requireIdCheckToPost`. Each change writes an audit event `settings.id_check.update` with before and after.
- **Default OFF.** A missing value is off in code. Migration `ensureIdCheckSetting` (`src/server/settings/id-check.ts`) stores `false` when the value is missing. Idempotent; never changes a stored value. Runs from the daily cron (`src/app/api/cron/expire/route.ts`, reported as `idCheckSettingSet`) and from the seed (`src/server/seed/run.ts`), like the hero migration.
- **Switch off.** `assertVerified()` returns at once. `evaluatePublishGate()` skips `VERIFICATION_REQUIRED` (new required input `idCheckRequired`). Callers: `submitListing` and the partner import (`lookups.requireIdCheck`, read once per import). Nothing writes `verificationStatus` and no "ID verified" chip is added.
- **Switch on.** Post-ad (`src/app/u/post-insert/page.tsx`) checks the status before step 1: `idCheckScreen()` gives `form`, `verify` or `checking`. `verify` shows "Verify your ID first" with a button to `/u/account/kyc/` (`src/components/post/IdCheckFirst.tsx`). `checking` shows "We are checking your ID". `PostWizard` gets `requireIdCheck`; its client pre-check runs only when on.
- **Unchanged.** 18+ check, adult tick, cleared media, category and word rules, people-category guard, KYC page.
