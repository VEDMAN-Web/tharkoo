# H19.1: Home, category and listing pages

## Done (the 8 items)
1. Cookie notice: hides itself after 30 s with no answer (`COOKIE_NOTICE_IDLE_MS`), nothing stored, so it counts as "Only necessary" for that visit.
2. Ad pop-out (Home card and listing row): a quarter smaller (width 75 % of the old size, never narrower than the card; the row pop-out photo, padding and text block are tighter). Its top and bottom are clamped inside the window (`pop-layout.ts`), measured with the layout height and watched with a ResizeObserver, and it has a max height of the window. It opens inside the window for a card at the bottom of the screen.
3. Category, listing and search pages: no Sort menu, no Verified / With photos / With video / Online now buttons, no "No filters for this category yet" line. A category's own yes/no filters and the accordions stay. The old URL parameters (`verified=1`, `sort=`) still work for old links; there is just no control for them.
4. State on opening a category: I could NOT reproduce a pre-selected state. On the seeded data `/dating/`, `/property/` and `/vehicles/` open with State = All states and City = All cities (new e2e on desktop and phone), and the code passes no state there. I added `autoComplete="off"` to the place selects, so a browser never refills a state from an earlier visit. If it still shows a state on live, send me the exact page address and what the State box shows: it would then come from saved data (a link with a state in it), not from this code.
5. Header account menu: closes on a press anywhere else, on Esc, and when the pointer reaches an ad card or its pop-out (`use-menu-dismiss.ts`), so it never sits over or under a pop-out.
6. Space above the footer: the footer's top margin is 24 px (was 88 px, 56 px on a phone) and the listing grid no longer adds 72 px (phone list 72 px bottom padding is now 24 px).
7. Support chat: the three quick buttons sit between the conversation and the message box, not under the greeting bubble.
8. Views and clicks on every ad card (Home card, listing row, both pop-outs, My ads card): an eye and a pointer with the number, "0" when none (`AdCardCounts`). I reused the existing counters (`ad_counters`, shown counts = admin-set value + real, once per visitor per ad). To match the definitions on the card:
   - views = ad page opens (unchanged: `AdCountsBar`). A card on screen no longer counts a view: the cards now only keep their numbers loaded (`holdAdCounts`) instead of the 1-second on-screen view.
   - clicks = a press of Call, WhatsApp, Chat or Video on the ad page (`ContactPressCounter`, new). Opening an ad from a card or pop-out is NOT a click any more (it was before). Old numbers already stored stay as they are.
