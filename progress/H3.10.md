# H3.10 — Partner CSV bulk import

## Done
- `src/server/listings/csv.ts`: small CSV reader (quotes, commas and line breaks in quotes, doubled quotes, CRLF/LF/CR, UTF-8 BOM).
- `src/server/listings/import.ts`: `dryRunImport` (writes nothing) and `runImport` (imports the OK rows).
  - Role: only `admin` or `superadmin`; `active` (publish at once) only for `superadmin`.
  - Partner is looked up by email and must be active and ID-verified (`assertVerified`, so `verificationStatus === "approved"`). An unverified partner is refused for both steps.
  - Max 200 rows (201 is refused) and 2 MB per file.
  - Columns: `category`, `city` (required), `district`, `title`, `description` (required), `photos`, plus one column per category field key. Category, city and district are slugs.
  - Per row it applies the same rules as the post form: title <= 140, description <= 5000, category enabled and not denied, city/district exist, `parseListingAttributes` on the category fields, `evaluatePublishGate`, `textDenied` plus the admin banned words on title, description and text attributes. Photos must be cleared images owned by the partner (our own `/uploads/...` path, a URL on our site host, or a Cloudinary URL whose key matches), and at most `photoLimit(false)`.
  - Duplicate guard: same title + category + city already in the file or already owned by the partner is an error.
  - Writing reuses `createDraft` and `patchListing` (basics, details, photos) from the listings service, so category/place checks and the forbidden-terms check run again. The result is then set to `pending` (seoNoindex true) or `active` (slug, publishedAt, expiresAt +30 days, seoNoindex false) and a listing version is written. Imported listings use `contact: { acceptForm: true }` (contact through the site form). They carry `attestations.importedBy/importedAt` and no `submittedAt`, so the partner's weekly free-ad count is not used.
  - Audit: one `listing.import` event (actor admin, target the partner user, `after` = rows, imported, failed, status).
- `src/app/admin/import/`: `page.tsx` (AdminShell, role gate), `ImportForm.tsx` (admin UI kit: TextField, DataTable, Notice), `actions.ts` (server action, session role check on the server).
- `tests/server/listings/import.test.ts`: 12 tests.

## Risks
- The policy deny-list (`ATTRIBUTE_DENY_TOKENS`) blocks any attribute key containing the token `price`, so the `price` column from the card cannot be stored on a listing today: a `price` value is reported as `This category has no field "price"`. Other category fields work. Needs a decision (a differently named category field, or a policy change by its owner).
- Free listings allow 1 photo (`LISTING_PHOTO_LIMIT_FREE`); rows with more photos are reported as errors unless that env value is raised.
- `createDraft` records `listing.create` audit events with the partner as actor; the admin appears in the `listing.import` event and in `attestations.importedBy`.
- Category/banned-word text check is a small copy of the service's private `assertCleanText` for the dry run (the service re-checks on write); `createDraft`/`patchListing` stay the single write path.
