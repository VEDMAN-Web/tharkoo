# H14.3 Seller dashboard, PR 1 of 2: the data

The UI (tiles, chart, rows, goal, moved switches, e2e, shots) is PR 2, branch haiku/h14.3b-seller-dashboard-ui.

## Done
- `src/server/listings/seller-dashboard.ts`: `sellerDashboard(userId, now?)` returns every number for the dashboard; `saveWeeklyGoal(userId, goal)` saves the goal on the user.
- `src/server/listings/dashboard-math.ts`: the pure parts (India days, Monday to Sunday weeks, % change, nice goal numbers, goal bounds 50 to 1,000,000, default goal, TOP lift, milestones).
- HARD RULE kept: views and clicks come from AdEvent (one row per visitor per ad; the owner's own visits are never recorded) and the real counters AdCounter.realViews / realClicks. viewsSet and clicksSet are never read (test D2).
- Bounded: at most 200 ads, one event aggregate over 14 days (by ad, type and India day), one order query for TOP windows, three counts for the lift of ONE ad, at most 5 ad rows each with a rank (up to 4 `queryListings` calls, the same query and default sort the public page uses: stars first, then the ranked feed without stars).
- New field `weeklyViewsGoal` on User (50 to 1,000,000, empty = default).
- New index on AdEvent: `{ listingId: 1, type: 1, createdAt: 1 }`. The dashboard counts events by ad, type and date range; the only index before it was the unique `{ listingId, visitorKey, type }`, which cannot serve a date range. MongoDB builds it in the background when the app starts.

## Decisions to check
- "TOP-type boost" means a PromotionProduct with code `top` (flash and auto-boost are not counted).
- Lift card needs: a TOP order that ended in the last 30 days, and the ad published at least 7 days before the boost started. A lift is shown only when views a day during the boost are above the 7 days before it and there were views before (never a number from zero). Otherwise the card shows no number.
- Weeks are Monday to Sunday in India. "Days left" counts today, so Sunday evening says 1 day left.
- Second button: "Bump" when the ad's views went up against the week before and it had at least 5 views; otherwise "Improve ad".
- The "Live ads" spark is the number of the user's ads live on each day, from their published and expiry dates (an ad removed since then is not in it).
- "Where it shows": `position` is stars first, then the ranked feed; `page` uses the public page size (15); `above` is the number of ads ahead. An ad that is not in the first 300 ads of its category and city has no rank (null).
