# H7.0: connectDb before every server query (hotfix for relay #67)

## Done
- `pickLimitsByCategory()` now calls `await connectDb()` first (the production build failure).
- Every exported server function or class method that runs a Mongoose query now calls `await connectDb()` itself. 166 functions in 60 files under `src/server/**`, including helpers reached only through exports. Six sync functions that returned a query were made `async` so they can connect: `categoryAdCount`, `subcategoryAdCount`, `adMediaCount`, `adVideoCount`, `refundEscrow`, `releaseEscrow`. Their callers already `await` them.
- Guard test `tests/server/db/connect-before-query.test.ts`: a static check (TypeScript AST) that fails when an exported server function queries Mongo without calling `connectDb()`, directly or through a helper in the same file or a named import from another `src/server` file. It runs in `npm test`, so CI catches this class of bug. It has a self-test that proves the guard flags the bad cases and not the good ones.

## Not done
- Nothing from relay #67 is left open in this PR. The Vercel production check is still pending after merge.
- Non-exported helpers are not checked directly; they are checked only through the exported functions that call them.

## Files changed
- `src/server/**` (59 files, connectDb calls and the six async conversions)
- `tests/server/db/connect-before-query.test.ts` (new)

## Risks
- The change touches many files, so review should check that the connectDb call is at the start of each function and does not run after a query.
- `connectDb()` throws `MongoConfigError` when `MONGODB_URI` is unset. Any code path that previously queried without a URI now fails at the same point with a clearer error.
