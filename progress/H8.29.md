# H8.29 (A29): listing copy resolver, no visible change

## Done
- `src/server/content/listing-copy.ts`: `resolveListingCopy(input)` and `explain(input)`. Nothing calls them yet, so the site does not change.
- Input: the page kind (category hub or place hub), its path, category and place names, count, and the same facts the pages already have. It reads the six sources: the content editor (ContentItem `listingIntro` for the path, published only), the per-URL override, `Site.landings`, the listing layout heading block, the SEO template and the built-in text.
- Legacy mode (default, `Site.listingCopySource` missing or "legacy") gives the same h1, intro, questions, title and description the category page and the city or state page give today. Tests compute today's result with the pages' own helpers and compare for each source.
- Content mode puts the content editor first, then the listing layout heading block, the SEO title and description templates and the built-in text. The old sources (URL override, Site.landings, SEO h1 and intro templates) are not used in this mode, as in the plan.
- `explain` lists, for every field, each source that has text, the winner first, and the mode.

## Not done
- Nobody calls it yet (the page wiring is a later card). District and sub-category pages are not covered yet (they only use the built-in text plus a URL heading).
- The band intro under the listing header is not part of this resolver.

## NEED
- A published ContentItem `listingIntro` has `body: unknown`. The resolver uses it as the intro only when it is a plain string; a rich document is ignored until the editor card defines the format.
- Today the SEO template intro can never win on category and place pages (the built-in intro is never empty). The resolver keeps it as the last candidate so `explain` still shows it.
- A saved SEO template title or description whose filled text is empty falls through to the next source here; today it would show empty text. This is an edge nobody has saved.
