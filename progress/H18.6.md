# H18.6 — vendor payouts in crypto (USDT via PassimPay) (Opus, 21 Nov 2026)

Done
- Vendors add a USDT wallet (TRC20 or BEP20, address checked, stored encrypted) with name + PAN. Bank/UPI are hidden until a payout account exists.
- Admin "Approve" on a crypto payout sends USDT through PassimPay POST /v2/withdraw (USDT TRC20 id 71, BEP20 id 72) and marks the payout paid with reference `passimpay:<transactionId>`.
- Rupees -> USDT at USDT_INR_RATE (server setting, default 88), rounded down to cents. Below 1 USDT is refused.
- PassimPay refusal -> payout failed, coins back to the vendor. Network error -> stays requested.
- Admin reveal shows the wallet; vendor summary shows it masked.

How verified
- npx vitest run tests/server/wallet/ — 7 files, 63 passed (4 new)

Risks
- PassimPay must hold enough USDT on the chosen network; otherwise the payout fails and the coins go back.
- PassimPay may require the withdrawal API to be enabled or an IP whitelist on the platform; check on the first real payout.
