# H6.12-videos: videos column in the partner import

Branch: `haiku/h6.12-videos` (from `github/main` 5c89a93, merged with main before the PR). Relay #58.

## Done

**1. CSV `videos` column** (`src/server/listings/import.ts`, `src/server/import/videos.ts`)
- File names separated by `|` (or `;`). Videos are chosen files only; a link in this column is a missing file.
- Up to 2 per ad (`VIDEO_MAX_PER_AD`). Each video is checked against the post-ad rule: mp4, webm or mov, at most 10 MB, at most 30 seconds, not empty.
- Row errors per video: `Missing file` (not among the chosen videos), `Too many videos`, the size, length and type messages, `listed twice`.
- The check counts the videos each ready row attaches, and lists chosen videos no ready row uses (`DryRunReport.videos`). Photo counts are unchanged.

**2. Choosing the files** (`src/app/admin/import/ImportForm.tsx`)
- One picker (`#import-images`) takes photos and videos, and the ZIP picker takes both. Files are sorted by type. A video's size, type and length are read in the browser (`clipSeconds` from the post-ad form, now exported).
- The dry run receives only size, type and length for each video, never the bytes.
- A ZIP entry has no browser type, so its type is set from the name. Before this change ZIP photos went up with an empty type and the server refused them. Fixed for photos and videos.
- ZIP entries are no longer dropped silently by the 8 MB reader limit. An oversized entry is refused with its reason in the check.

**3. Upload and resume** (`src/server/import/job.ts`, `src/app/admin/import/files/route.ts`)
- The upload route moved from `admin/import/photos/` to `admin/import/files/`. It takes `kind=video` for a video.
- `recordImportVideo` checks the real bytes (type, size, length from the container) before storing, so a browser that misreports a clip is refused.
- Storage: Cloudinary as `resource_type: video` when it is set up (`UploadOptions.resourceType`), otherwise this server's disk. On Vercel without Cloudinary the upload is refused with a clear message, the same as photos.
- The job saves the chosen videos (`videoFiles`), the ones to upload, and the ones stored. A reload resumes from the saved row, the same as photos. The row loop attaches each video with `MediaAsset.listingId`, as post-ad does.

**4. Template and help** (`src/server/import/template.ts`)
- `videos` column added at the end. Example row 1 names `hero-cycle-ride.mp4`.
- Plain-English help line: `videos: list the file names of the videos you choose, separated by |. Up to 2 per ad. ...`.

**5. Audit**
- `listing.import.start` records `videos` (count to upload).
- `media.import.upload` records `kind` (`image` or `video`) for each file.
- `listing.import` records `videos` (count attached).
