# H1.3 — Crawler-safe rate limiting

**Result:** DONE. PR open (branch `haiku/h1.3-rate-limit`). Opus reviews line by line. Waiting for Opus.

## Done
- `src/lib/rate-limit.ts`:
  - `clientKey`: uses the **last** non-empty `x-forwarded-for` entry (the one our Nginx appends), then `x-real-ip`, then `"local"`. One-line comment says why.
  - New exported `limitBucket(path, method, userAgent)` → `{ bucket, envName, fallback }`, with the card's rules and order: `search` (`/search`, `/api/catalog`, 30) → `api` (`/api/` or non-GET/HEAD, 240) → `bot` (GET/HEAD and the bot UA list, `BOT_RATE_MAX`, 1200) → `page` (everything else, 240). Type `LimitBucket` exported.
- `src/proxy.ts`:
  - Imports `limitBucket`. Key is `${ip}:${bucket}`. Limit from `requestLimit(envName, fallback)`.
  - `routePath` is `rewriteTo` when it starts with `/search`, otherwise `path`, so a rewrite to search still counts as search (as before).
  - Only `api` and `search` use the Mongo `consumeRateLimit` (with in-memory fallback). `page` and `bot` use the in-memory `allowRequest` only.
  - New `tooManyRequests(bucket)`: every 429 has `Retry-After: 60`. `page` and `bot` return `text/plain` "Too many requests"; `api` and `search` keep the JSON body.
- `tests/server/proxy/rate-limit.test.ts` (new): 7 tests — last XFF entry, empty entries, fallbacks, bucket for `/`, `/property/surat/`, `/search/`, `/api/catalog`, `/api/listings/`, POST `/u/login/`, Googlebot on GET/HEAD, search and api ahead of bot, and `allowRequest` blocking the (max+1)th call.
- Not changed: `src/server/auth/rate-limit.ts`, `src/app/api/**`, origin check, redirects, 410 logic.
