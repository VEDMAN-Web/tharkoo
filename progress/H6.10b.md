# H6.10b: Page titles tab and page title blocks on the Listing pages and Post-ad page (relay #49 items 2 and 3)

## Done
- **Admin → SEO → Page titles** (new first tab, `/admin/seo/page-titles/`): a searchable list of every page type, grouped in plain English: Home page, Category pages, City and state pages, City pages one category at a time, District pages, Sub-category pages, Ad pages, Country pages, Other pages. Each row shows its address, title and description, and whether the text is saved or built in. **Edit** opens an inline editor (same counters 30 to 65 and 70 to 160, same live search preview). **Reset to template** clears the saved text for that row.
- **Admin → Listing pages**: "Page title & description (SEO)" block under the scope picker, bound to the stored value the chosen scope already reads: all listing pages = the category template default (`SeoTemplate` `category`); one category = `SeoTemplate` `category:<slug>`; one exact address = `UrlOverride` for that address.
- **Admin → Post-ad page**: the same block at the top, bound to the `UrlOverride` for the post-ad address (the value `withUrlSeo` reads on that page).
- Shared component: `SeoTitleSection` (src/components/admin/SeoTitleSection.tsx). The Home page block (H6.10) now uses it too; its behaviour and save path are unchanged.
- Save rules (one place, `checkPageTitle` in src/server/seo/page-titles.ts): admin only for the editors, any SEO editor for the tab (home needs an admin). Refuses empty text, em or en dashes, text over 120 characters (title) or 320 (description), and blocked words. Writes through the existing paths (`saveTemplate`, `saveUrlOverride`, `applyHomeSeoChange`), which audit the change. Other stored content (heading, intro, FAQ, robots) is kept.
- Reset rules: a category's own template with no heading or intro is removed (the category inherits again); otherwise title and description are cleared. An exact address with nothing else set is deleted; otherwise only title and description are cleared. The home page goes back to the built-in title and description.
- Tools tab and "Remove long dashes from saved text" are unchanged.
- Tests: tests/server/seo/page-titles.test.ts (21 tests: target parsing, the save rules, saved content kept, who may save, reset, every page type in the list, district fallback).

## Not done or different from the brief
- **Ad pages** are read-only in the list. The ad page builds its title from each ad (`{title}, {city} {category} | {site}`), and nothing is stored for it, so there is nothing to bind an editor to.
- **City pages** have no per-city stored value. The list shows the city and state default, plus one row per category ("City pages, one category at a time"), which is the stored value the city pages read. A title for one exact city page is still set in Page overrides.
- **Built-in copy** for the fixed pages (cities, countries, blog, help, contact, search, log in, create account, post an ad, country pages) is copied into src/lib/seo/page-title-defaults.ts. It is shown only when nothing is saved and does not change the pages. If one of those page titles changes in code, update the copy there too.
- The Listing pages block describes the category default for "All listing pages". City and district defaults are edited in the Page titles tab.
