# H6.18: one ad media limit (10) and the tharkoo.com watermark

Branch: haiku/h6.18-media-watermark (from github/main 1f40796).

## Done

1. **One limit for every ad: 10 photos and videos together.** Free, promoted, admin Create ad and partner import.
   - Server checks: upload sign (`signMedia`), reorder, attach and submit (`assertPhotos`, `submitListing`), admin create (`checkAd`), partner import rows (`resolvePhotos`, `resolveVideos` and a row total).
   - Old `photoLimit` (free 1, promoted 10, env vars) and `VIDEO_MAX_PER_AD` (2) are gone. `photoLimit()` is kept as a shim that returns 10, so `src/server/import/rules.ts` still compiles (see NEED).
   - Per-file rules are unchanged: photos 8 MB; videos 10 MB and 30 seconds; mp4, webm, mov.
   - Category `importMaxPhotos` is an upper bound for imports, capped at 10 (`importPhotoLimit`).
   - Post-ad counter reads "N of 10 photos and videos" (`PhotoStep.tsx`).
2. **Watermark, burned in at upload (one approach).**
   - Cloudinary: an incoming transformation on every ad upload (listings folder). Cloudinary stores the transformed file, so the stored original already carries the mark. Stripping the transformation from a public URL returns the marked file.
   - Local disk (no Cloudinary, dev only): sharp draws the mark on photos before the file is written. Videos are refused while the watermark is on, because there is no video tool on the server.
   - Text "tharkoo.com", bottom right by default, about 22 percent of the width, semi-transparent.
   - Settings: Admin > Settings > Watermark (superadmin only, audited as `settings.watermark.update`). On/off (default on), position (4 corners or centre), opacity (10 to 100, default 60). Stored in `watermark_settings`.
   - Not applied to site media, ID documents, or chat images.
   - A marker collection (`watermarked_media`) records which stored files carry the mark, so nothing is marked twice.
3. **Existing ad media.** `watermarkExistingAdMedia` runs from the daily cron (`src/app/api/cron/expire/route.ts`). It downloads each unmarked Cloudinary ad original and re-uploads it under the same public id with the mark. Idempotent (a marked file is skipped). Batch of 10 per run. The cron response reports `adMediaWatermarked` and `adMediaWatermarkFailed`.
4. **Tests.** New `tests/server/media/watermark.test.ts` and `tests/server/listings/ad-media-limit.test.ts`. Updated `media.test.ts`, `my-media.test.ts`, `video.test.ts` to the new rules.

## Risks

- The Cloudinary text-layer syntax (`l_text:Arial_100_bold:tharkoo.com,co_white/c_fit,w_0.22,fl_relative,o_60/fl_layer_apply,g_south_east,x_16,y_16`) follows Cloudinary's docs for relative text widths. Not tested against a live account. A malformed transformation would fail uploads, so check one real upload on www first.
- Incoming transformation on video is applied during upload; large videos may take longer to upload.
- Migration downloads each original from its public URL. Batch size is 10 per cron run.
- Locally (no Cloudinary) with the watermark on, ad videos are refused. Turn the watermark off in Settings to test local video uploads.
