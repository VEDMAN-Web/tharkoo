# H6.21 support tickets: replace the Support desk stub with real tickets

NOT REVIEW PLEASE. Support ticket system for users, vendors and staff. No payments, coins, ads or auth logic changed.

## Done
- Admin Support desk (`/admin/support/`) replaces the CMS-page stub. Queue with filters (status, topic, user or vendor, assigned to me), oldest customer message first, customers waiting for support first, age of the last customer message.
- Staff thread (`/admin/support/[id]/`): reply, internal note, assign, change status, Close (with confirm) and Reopen. Only the roles support, moderator, admin and superadmin can use the desk.
- Owner side (`/u/account/support/`): list with status chips and unread marks, New ticket (topic, subject, message, up to 3 screenshots of 5 MB each, JPEG/PNG/WebP only), thread with reply box. Owners cannot close (403). A closed ticket is read only, with "Open a new ticket".
- Models: `SupportTicket`, `TicketMessage` (`src/server/models/support.ts`), `SupportAttachment` (`src/server/models/support-attachment.ts`). Screenshots are stored in the database and served only by `/api/support/attachments/[id]`, which checks the viewer. No public URL.
- Internal notes never reach the owner: the owner thread query filters them out, and the attachment route refuses screenshots on internal notes.
- Audit rows: `support.open`, `support.reply` (both sides), `support.note`, `support.status`, `support.assign`, `support.close`, `support.reopen`, `support.view` (staff opening a thread).
- Unread marks on both sides (`unreadForOwner`, `unreadForStaff`). In-app notice on the account dashboard and on the admin dashboard. Email only when `BREVO_API_KEY` is set (via `src/server/mailer`); the email has a link, not the reply text.
- Rate limits, counted from the database: 5 ticket openings per hour per user, 20 replies per hour per user. Opening messages do not count against replies.
- Plain text only: tags and control characters are stripped on write; text is rendered as text, with no links turned into anchors.
- Zod validation at every route boundary. Image type checked from the bytes (`imageMatchesType`, shared with chat).

## Risks
- The 390 px horizontal-scroll fix on the staff thread page was found by the e2e run (the admin stack column grew to 400 px). Fixed with a single `minmax(0, 1fr)` column on that page. The same pattern is untested on other admin screens.
- Rate-limit counters count database rows, so they are accurate across instances but cost one count query per request.
- Ticket numbers come from a counter document; if the counter is reset manually, numbers would repeat (the unique index on `number` would then reject the insert).
