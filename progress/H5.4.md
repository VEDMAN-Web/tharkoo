## Done
- Priority (fetchpriority high) photos can no longer sit at opacity 0 until hydration (`.tk-motion .tk-fade-img:not(.is-loaded)` hid the LCP image, so the browser could not count it). Override in `src/components/blocks/blocks.css` (home, listing) and `src/app/ad/[slug]/ad-perf.css` (ad page).
- Ad page: chat panel code is loaded after the page (`src/app/ad/[slug]/LazyChat.tsx`, dynamic, no SSR), so it leaves the initial client JS.

## Tried and dropped (measured, no gain or worse)
- `images.formats` with AVIF: files 25-30% smaller (24 KB -> 17 KB) but the score did not move; images are already 7-28 KB. Dropped to avoid sharp AVIF CPU cost on the small server.
- `experimental.inlineCss`: FCP 1.56 s -> 1.38 s but TBT rose (listing 454 ms, ad 547 ms) and scores fell to 78/75. Dropped.

## Not done / what blocks 90 on the ad page
- Simulated LCP stays near 3.5 s on every page because it tracks the shared client JS (about 160 KB first load: next client chunk 1386 and react chunk 2caa01da, plus the site shell), not image bytes (LCP images are 7-28 KB).
- NEED: src/components/SiteShell.tsx and src/app/layout.tsx because the shared shell client JS is the remaining cost (hydration, MotionInit forced layout).
- NEED: src/components/AdDetail.tsx and src/components/ui/Gallery.tsx because the gallery, related cards and save/contact client code load with the ad page and cannot be lazy-loaded from src/app/ad/**.
- NEED: src/app/globals.css because the fade rule lives there (override added in owned files instead).
