# H21.6 - Buy credits popup (standalone component)

## Done
- src/components/post/BuyCreditsDialog.tsx (+ buy-credits-dialog.css, post.v2.buy.* keys). Props: { need, price, plan, balance, onPaid(newBalance), onClose }.
- Centred 480 px dialog on a computer, bottom sheet with a grab handle on a phone, no inner scroll, focus trap and Esc (the shared useFocusTrap).
- Title "Add ad credits"; the line "You have {bal} credits. {plan} needs {price}, so you need {need} more."; the ad packs from GET /api/payments/packs (ad wallet, shortfall = need), the smallest pack that covers the need already chosen with an "Enough for this" tag (the biggest pack when none covers it); "Or enter your own amount" using the limits the server sends (smallest, most per payment, most per day) and the same credit sum as the server (creditsForAmount); the "Your ad is saved..." note; "Pay Rs {amount}".
- Pay: POST /api/payments/recharge (ad wallet, card). A blank tab is opened inside the click (so it is not blocked) and pointed at the payment page; the draft and step stay in the return URL (the current URL is sent). The dialog switches to "Waiting for your payment" with a spinner and "Open the payment page again". It asks GET /api/payments/{id} every 3 s (stops after 30 min) and again when the window gets focus or the tab shows.
- Paid: "{n} credits added", the new balance (read from the wallet), "Publish with {plan} · {price} credits" and "Back to review". The header pill and balance lines are refreshed through the existing credits event (count 0, so it does not start a publish by itself).
- Failed, expired or cancelled: "Payment did not go through" / "Nothing was charged." and Try again.

## How Lane A wires it
- Render <BuyCreditsDialog need price plan balance onPaid onClose /> while an open state is true.
- onPaid(newBalance) is called when the person presses "Publish with ..." (that is the cue to publish straight away); onClose is "Back to review" and the X / Esc.
- Coming back by URL (tab closed) is the wizard's job: the dialog keeps the page URL as the return URL, so Review reopens on the same draft and step.
