# H6.12: bulk upload (media batch and partner import with photos)

Branch: `haiku/h6.12-bulk` (base c716add). Lane C, relay #55 and #57.

## Done

**1. Media library batch upload** (`src/app/admin/media/BatchUpload.tsx`)
- Picker and drag and drop, up to 50 files per batch, each up to 8 MB, jpeg, png or webp only (checked in the browser and again on the server from the real bytes).
- Per-file list: queued, uploading, done, failed with the reason. Refused files are listed with the reason and never sent.
- Three uploads at a time. A network failure is retried once automatically. "Retry failed" re-sends the failed files.
- Alt text is filled from the file name (`red-sofa_01.jpg` gives "Red sofa", rule in `src/server/media/alt-from-filename.ts`) and marked "Auto alt, check it". The "Images missing alt" filter still lists them. Saving a card clears the mark.
- `SITE_MEDIA_MAX_BYTES` is now 8 MB (was 5 MB).

**2. Partner import with photos** (`src/app/admin/import/`, `src/server/import/`, `src/server/listings/import.ts`)
- One screen: partner email, CSV, and either the chosen images or one ZIP (read in the browser by `src/server/media/zip-images.ts`, no new package).
- `photos` column: file names separated by `|`. An uploaded URL still works. Parsing in `src/server/import/rules.ts`.
- Step 1 (dry run) counts ads, photos to attach, images to upload, and chosen images that no ready row uses (those are reported and not uploaded). Missing file names are row errors.
- Step 2 saves an import job first (`src/server/import/job.ts`, model `src/server/import/model.ts`). Only the referenced images are uploaded, three at a time, to the partner's listing photos. Then rows are imported in blocks of 25 with a progress bar.
- The job is saved in the database. After a reload the page offers "Continue import". Photos already sent are skipped, and the same images must be chosen again. A lock with a 2-minute stale limit stops two windows running the same job.
- Row cap is 500 (`MAX_IMPORT_ROWS`).
- Template: `/admin/import/template/` (every base column, two example rows). Plain-English help is on the page.
- Photo limit: a superadmin import uses the category `importMaxPhotos` (default 10 when empty). Other admins keep the free limit.
- Import photos skip the plan photo step (`attachPhotos`), because that step enforces the plan limit and would refuse the superadmin maximum. The limit is checked by the import rule instead.

**3. Audit**
- `media.site.upload` (now records `autoAlt`), `media.import.upload` (each import photo), `listing.import.start` (job created), `listing.import` (job done, with `jobId`).

## Not done
- No admin screen for the category maximum yet. The field exists (`Category.importMaxPhotos`, 1 to 30). Set it in the database, or add a field to the categories admin in a follow-up.
- Import photos stored on the local disk (no Cloudinary) are not EXIF-stripped. The Cloudinary path uses the same `fl_strip_profile` transformation as signed listing uploads. Cloudinary eager sizes are not generated for import photos (delivery transforms on request).
- Next's default server action body limit is 1 MB. A 500-row CSV is about 100 to 200 KB and is fine, but a CSV near the 2 MB cap may be refused by Next before the import sees it.
- One image used by two rows is attached to both listings. `listingId` on the photo points to the last row.

## Risks
- The superadmin photo maximum has no UI, so the default of 10 applies everywhere until it is set in the database.
- A job whose browser closes during a chunk leaves a lock for up to 2 minutes. After that the next visit continues it.
- Partner import reuses the existing duplicate-title check. A row saved just before a reload is reported as a duplicate on resume, not imported twice.
