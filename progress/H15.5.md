# H15.5 (FIX-5, E1-B5): Save search no longer throws a script error

## Cause
`AlertsPanel.create` called `event.currentTarget.reset()` after waiting for the server. By then the event's `currentTarget` is gone (null), so saving ended in "Cannot read properties of null (reading 'reset')" and the form was never cleared.

## Fix
`src/components/buyer/AlertsPanel.tsx`: the form is kept by a ref (`formRef`), cleared with `formRef.current?.reset()`; the list updates through the existing `router.refresh()` (no page reload).

## Test (first: failing on main, then passing)
`tests/e2e/h15-5-alerts-form.e2e.ts`: save a search with words and a category: no script error, the confirmation shows, the form is cleared, the list shows the new alert with no full page reload, Remove updates the list.
- On main (build of 6366c9f): 2 failed (both projects), "Cannot read properties of null (reading 'reset')".
- With the fix: passes at 1440 and 390; with user-panel and h12-3-panel-align: 16 passed, 4 skipped by design.
