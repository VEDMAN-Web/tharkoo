# T2.2

## Done
- `POST /api/media/sign` returns a Cloudinary signature for a direct browser upload. The signed params include `timestamp`, a folder under `CLOUDINARY_FOLDER_PREFIX`, `public_id`, and `transformation=fl_strip_profile`. Listing photos also sign eager derivatives: card 480w, detail 1280w, thumb 200, each with `f_auto,q_auto` and the EXIF strip.
- `POST /api/media/complete` checks the object with the Cloudinary API, runs the CSAM scanner, and stores the asset as `scanning` owned by the signed-in user. Another user gets `NOT_FOUND`.
- JPEG, PNG, and WebP only, at most 8 MB. A missing session is `401`. Mutations use the T2.1 origin check.
- Listing photo cap is 1, or 10 when the listing has a non-`free` badge or an active promotion order. `LISTING_PHOTO_LIMIT_FREE` and `LISTING_PHOTO_LIMIT_PROMOTED` override those defaults.
- ID documents are signed with `type=authenticated`, are not given eager public derivatives, and are not returned with a `res.cloudinary.com` delivery URL. `signedIdDocumentUrl` builds a short-lived private download URL (120 seconds) for T2.3.
- `GET` and `DELETE /api/media/{id}`, and `PATCH /api/media/reorder`, follow the contract. Sign, complete, delete, and reorder append an audit event.
- `scripts/media-orphan-sweep.ts --dry-run` lists stale `uploaded` rows older than 24 hours and remote objects under the prefix that are not in Mongo. Without the flag it destroys them.
- Missing `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, or `CLOUDINARY_FOLDER_PREFIX` fails the request with `INTERNAL` and the missing names. Importing the module does not throw, so `next build` still succeeds.
- CSAM is a stub (`CSAM_PROVIDER=stub` or unset). Any other provider name fails closed. No KYC vendor SDK.

## Not done
- No separate `ListingPhoto` collection. A listing photo is a `MediaAsset` with `kind: "image"` and `listingId`. The data model already stores photos that way.
- `GET /api/media/{id}` returns metadata and status only. It does not return derivative URLs. The browser builds the upload from `params` and `uploadUrl` on the sign response.
- Staff download of an ID file stays on T2.3 `GET /api/admin/verifications/{id}/file`. This task exposes `signedIdDocumentUrl` for that route to call.
- The live CSAM vendor is still the stub. A match sets `rejected_csam` and returns `POLICY_VIOLATION`.

## API changes
- No edits to `docs/contracts/API.md`.
- Sign `data` adds `params` (the exact map that was signed) and `uploadUrl` (`https://api.cloudinary.com/v1_1/{cloud}/image/upload`). The contract fields `timestamp`, `signature`, `cloudName`, `apiKey`, `folder`, and `mediaId` are unchanged.
- Video `kind` is `POLICY_VIOLATION`. The Zod schema still allows it; the service rejects it.
- Over the photo cap is `POLICY_VIOLATION` (`Photo limit reached`).
- A missing Cloudinary env var is `500` `INTERNAL`.
