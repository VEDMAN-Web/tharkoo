# H7.3: dynamic fields and filters (admin side), relay #63

Branch: haiku/h7.3-fields (from github/main fc105fe).

## Done

- **Option store.** Options live in their own collection (`category_field_options`, unique per field on a lower-cased
  value, ordered). Admin only: list with search and paging, add (paste one per line, or the first column of a CSV),
  remove. Repeats and banned wording are refused line by line; a list is capped at 5,000 per field.
- **Mirror.** Each change writes the option values back onto the category field (`fields[].options`), so the existing
  listing checks (`parseListingAttributes`) refuse any value that is not in the admin list. Lists that predate the
  collection are copied in on first use.
- **Field settings.** Per field: filter name (`category_field_settings`, max 40 characters), most picks (pick-many only,
  1 to 50, empty = no limit), switches for post-ad (`enabled`), filter (`filterable`) and required, and a type switch
  between pick-one and pick-many. A field cannot go on the post-ad form with no options.
- **Add field.** Five kinds (pick many, pick one, number range, yes or no, short text). The key is made from the label
  and kept unique; the field starts switched off.
- **Admin screen.** `Categories > a category > Fields and filters` now shows the mockup layout: field list with
  switches, selected-field panel, option chips with search and "show more", paste box, CSV import, save bar at the top.
  Keyboard users can move a field with Move up / Move down; drag also works.
- **Filter rules (pure, tested).** A filter is any query parameter with a value, except tracking parameters. Filter
  URLs get `noindex, follow` (`listingRobots`). Only category, category+city and category+city+area count as indexable
  (`indexableListingKind`, `isIndexableListing`). Field filters parse as `f.<key>=<option>` with at most 20 picks each.

## Risks and decisions

- Mirror: the category document keeps a copy of each option list. A list of thousands makes the category document larger.
- Removing an option does not change ads that already use it. Editing such an ad later fails validation until the value
  is listed again. Left as is on purpose; the admin is told the option is removed from the list only.
- Admin colours: the admin screen uses the `--adm-*` tokens (admin rule). The mockup's rose and violet palette is not
  applied to the admin screen.
- Type change is allowed only between pick-one and pick-many. Other types are read-only in the editor.
