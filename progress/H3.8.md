# H3.8 - Listing order control

## Done
- `rankScore(listing, promotions, now, settings?)` and `compareRank(a, b, settings?)` take optional `{ tierOrder, verifiedFirst, photoFirst }`. Without settings (or with `DEFAULT_RANK_SETTINGS`) the order is the original one: proven by a 30-listing fixture whose expected order (`tests/server/ranking/default-order.json`) was captured from the unchanged code and committed first.
- Order inside a tier: verified (if on), photo (if on), freshness, then slug. A promotion changes the tier only when it is active; ads with no active promotion sit at the position of `free`.
- Pins: `ListingPin` model (collection `listingpins`) and `applyPins` in `src/server/ranking/pins.ts`. Applied after sorting, over the full list (so a slot is stable across pages). Used only when the pin is inside its dates and its ad is in that feed (active, matches filter, not hidden). Scope comes from the query: `home`, `hub:<cat>`, `hub:<cat>/<city>`, `hub:<cat>/<city>/<district>`. Search, related ads, single-ad and star-only queries get no pins.
- `feedHidden` on Listing: skipped by every feed/count query except a lookup by `slug`, so the ad page still loads.
- `ranking` field on the Site document (`loadRankSettings` falls back to defaults).
- Admin screen `/admin/listing-order/` (admin/superadmin): sortable tier order, two toggles, page chooser, Preview (first 20 ads with unsaved settings), pins table for the chosen page (add by ad ID or URL, position, dates, remove), hide/unhide. Every write checks the role on the server, is audited (`listing-order.*`) and refreshes the public cache.
- Sidebar item now links to the real page (removed the `"H3.8"` marker).

## Not done
- Pins are keyed by category/city/district slugs as given in the URL; the admin screen offers category + city only (district pins work in the model but have no picker).
- Sitemaps and other direct `Listing.find` readers still include hidden ads (they are still reachable by URL).
