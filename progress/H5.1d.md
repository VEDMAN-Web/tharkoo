# H5.1d: BUG 5 webhook origin and signature (relay #30)

## Done
- The Origin check no longer applies to POST /api/payments/webhook (src/proxy.ts). The route checks the signature and timestamp instead.
- Signature: x-payment-signature = HMAC-SHA256(PAYMENT_WEBHOOK_SECRET, "<x-payment-timestamp>.<raw body>"), compared in constant time.
- Timestamp: must be within 300 seconds of now (replay of an old request is refused).
- A refused webhook returns 400 (INVALID_SIGNATURE) and writes an audit row payment.webhook.rejected with only the reason (missing, stale or bad-signature). No body, signature or secret is stored.
- Replays of a valid event are idempotent (existing providerEventId check; second delivery credits nothing).
- Razorpay's own x-razorpay-signature header is no longer accepted: its scheme is different, and the provider is not live.
- Tests: tests/server/billing/billing.test.ts (valid, replayed, bad signature, stale, missing timestamp). The BUG 5 e2e test in tests/e2e/money.e2e.ts is un-skipped; tests/e2e/helpers.ts signs with the timestamp.
