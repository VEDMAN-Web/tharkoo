# H6.10: Home page title and description in the Home page editor (relay #50, #49 items 1, 4, 5)

## Done
- **Admin → Pages → Home page** (`/admin/homepage/`): new section at the top, "Page title & description (SEO)". It reads and writes the same stored fields the public page reads: `Site.homepage.content.seoTitle` and `seoDescription` (the document with key `default`, read by `getHomepageContent`). The old SiteContentForm "home" part is still in the code but not rendered; nothing else was removed.
- Counters: title 30 to 65 characters, description 70 to 160 (the TextField counter, amber below the minimum, red above the maximum). Live Google-style preview (desktop and mobile) with the existing SerpPreview.
- Save: `saveHomeSeoForAdmin` → `applyHomeSeoChange` (src/lib/ui/site-store.ts). Role check (admin or superadmin), refuses empty text, dashes (same message as the other admin saves) and text over the stored limit (120 / 240). Writes through `applyHomepageChange`, so the audit entry (`site.homepage.update`) and the cache refresh are the same as the homepage save. The rest of the homepage content is kept.
- Revalidation on save and repair: `refreshPublicCache()` (drops the in-memory and tagged caches for site, categories, locations, feed, listings, counts and calls `revalidatePath("/", "layout")`). The repair now calls it when it changed something (it did not before).
- **Repair (Tools)**: the repair already walked `Site.homepage` (the default document); a seeded test confirms the homepage title, description and hero text are repaired and a second run changes nothing. The missing piece was the cache refresh.
- **Descriptions**: the repair gave `seoDescription` a " | " separator (the key matches "seo"). It now gives descriptions ", " so a repaired description reads as a sentence. Titles still get " | ".
- **Tools button** (#49 item 5): renamed to "Remove long dashes from saved text", with the line "To edit page titles, use the Page titles tab." under it. The Page titles tab is a later item.
- Ownership: `docs/ownership.json` entry "H6.10".

## Not done
- The Page titles tab (later item).
- Not verified on the live site. The cause of "still shows" is not confirmed: the repair code path reaches the default document, so the most likely causes are (a) the old cache (no refresh after the repair, up to 60 s in memory and in the ISR/unstable_cache layer), or (b) the repair ran against a different database from the one the site reads, or (c) the stored title used a dash character other than em or en (not matched by DASH_CHARS). Vedant or Opus should check which environment the button ran in.
