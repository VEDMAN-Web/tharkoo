# Tharkoo MASTER_PLAN (v1, 10 Nov 2026) - owner: Ana. Read CODE_MAP.md first.
Goal: premium, SEO-first, real classifieds platform (own brand, no reference-site assets/copy), mobile-first, admin-editable catalogue, deployed on DigitalOcean (droplet 143.244.141.17, BLR1). Stack stays Next.js (App Router) + MongoDB + Mongoose; backend logic ported from sbt-private-product into this repo (single Node process).

## 0. Gate G0 - scope and content policy (NOT decided by Ana; needs Ved + legal)
Today's seed/SEO copy in tharkoo is explicit commercial sexual-services advertising ("Call Girls", "erotic massages... all sexual services", "Male Escorts", "Adult Classifieds"), and reference-site's "Star (escort only)" product. The older sbt-private-product repo deliberately banned these (deny-list, ID+18 gate, CSAM scan, trafficking reporting). Risks: trafficking/CSAM liability, Indian law (ITPA/IT Act), payment gateways (Razorpay/Cashfree/Stripe) and Cloudinary/Brevo/Cloudflare/DO acceptable-use policies all prohibit it; accounts can be terminated.
**This plan therefore builds the sbt content policy:** category allow-list (seed: dating, friendship, meetups, personal; more only via admin + deny-list check), deny-list for escort/sexual-service/companionship-for-pay terms in categories, attributes, copy and promotion products, mandatory ID + 18+ KYC before first publish, CSAM scan hook, trafficking report path with SLAs, moderation-before-index, immutable audit log. "Star" becomes a generic premium-slot product. No task seeds, writes copy for, or SEO-targets sexual-service queries. Any widening of scope = a written decision from Ved after legal advice; the deny-list is a config in `src/server/shared/policy.ts` so the decision stays one reviewed PR.

## 1. Principles for every agent
1. Contract first: `docs/contracts/API.md` + zod schemas (T1.1) are the single source of truth; UI tasks consume them, never invent endpoints.
2. One task = one branch = one owner = non-overlapping paths (docs/ownership.json, enforced in CI). Touching a path you do not own = stop and write `progress/<task>.md` "NEED:" note instead.
3. Karpathy rules (`.cursor/rules/karpathy-guidelines.mdc`, mirrored in AGENTS.md): smallest change, state assumptions, verifiable success criteria, surgical edits.
4. Graphify before exploring: `pip install graphifyy && graphify update .` (AST only, ~3 s, free) then `graphify query/path/explain`; re-run `graphify update .` before PR. `graphify-out/` is git-ignored (each agent builds its own).

6. No secrets in git, ever (section 9). gitleaks in CI.
7. Test mode only for payments/KYC/SMS until Ved + Ana flip a documented switch; real money never moves in this plan.

## 3. Git workflow
- `main` is always deployable. Branch per task: `cursor/<task-id>-<slug>` or `codex/<task-id>-<slug>`. Codex: rename local `codex/phase-0-stabilization` to `codex/t0.2-lint-types` after `git fetch origin && git rebase origin/main`; never push other local-only history.
- Start of task: `git fetch origin && git switch -c <branch> origin/main`, `graphify update .`, read `PROGRESS.md` + `progress/*.md` of dependencies.
- During: small commits quoting the task id (`T2.1: ...`). PR <= ~400 changed lines excluding lockfile/tests; split otherwise.
- Before PR: `git fetch && git rebase origin/main`, `npm run lint && npm run typecheck && npm test && npm run build` green locally, write `progress/<task-id>.md` (done / not done / API or schema changes / how verified / next).
- Deps rule: all planned packages are installed once in T0.3 (zod, bcryptjs, cloudinary, @getbrevo/brevo or fetch, vitest, @playwright/test, mongodb-memory-server, pino, @axe-core/playwright, gitleaks via CI). Later tasks may append a package only if listed in their brief; after any rebase conflict in package-lock.json: take main's lockfile and run `npm install` (never hand-merge).
- CI (T0.1, required checks): lint, typecheck, test, build (with MONGODB_URI unset), gitleaks, ownership-check (diff paths subset of the task's paths in docs/ownership.json), forbidden-terms check (policy deny-list grep on src/ + seed).
- Merge: only Ana, squash-merge after audit (CI green + diff within ownership + acceptance list re-run + one S-tier review on S tasks). Agents never merge, never force-push main, never push to another agent's branch. Merge order follows dependencies below; after each merge Ana updates `PROGRESS.md` (index) and notifies the other platform's next task.
- Shared files with single owners: package.json/package-lock.json (T0.3, append-only after), next.config.ts (T0.3), src/app/globals.css + src/styles (T8.1), src/lib/db.ts (T0.3), `docs/contracts/**` (T1.1; changes via PR to that owner), `PROGRESS.md` (Ana only), `progress/<task-id>.md` (that task only).
- Handoff between platforms = files in repo only: `PROGRESS.md` (index: task, status, branch, PR, owner, blockers), `progress/*.md`, `docs/contracts/*`, `docs/HANDOFF.md` (points to these). No chat-only knowledge.
- Release: tag `v0.N` on main after each phase gate; deploy = tag push (section 8).

## 8. Deploy on DigitalOcean (decision)
**Droplet:** keep the existing `ubuntu-s-1vcpu-1gb-blr1` (143.244.141.17, Ubuntu 24.04) for app only. 1 GB is enough to RUN one Next.js standalone process (~150-250 MB RSS) + Nginx (~10 MB) + OS (~200 MB) + PM2 (~50 MB); it is NOT enough to run `next build` (needs ~1.5-2 GB) or MongoDB (needs >= 500 MB). So: **build in GitHub Actions, ship the standalone bundle** (`.next/standalone` + `.next/static` + `public`, ~60 MB tarball), no `npm install`/build on the server. Add 2 GB swap (`vm.swappiness=10`), Node `--max-old-space-size=256`, image optimization off (Cloudinary does it) so `sharp` is not needed.
